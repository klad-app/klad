# klad: design

A 2D art application built for agents first and humans second, for professional game assets in any style.

An agent drives it through a CLI and sees results as PNG renders. A person with a pen opens the same file in a native editor to edit, add detail and animate. Both work on one document on disk at the same time.

## Principles

1. **Everything is addressable.** Layers, cels, vector nodes and individual paint strokes have ids. An agent never has to describe something by its pixels.
2. **One set of pixels.** The CPU produces every pixel, in the CLI and in the editor, from the same code. What the agent renders is what the human sees.
3. **Non-destructive by default.** Paint layers keep their strokes, vector layers keep their geometry, filters and adjustments keep their settings. Baking to plain pixels is an explicit choice.
4. **Time is in the model from the start.** Every layer's content lives in cels on a timeline. A still image is a one-frame document.
5. **Edit and see in one call.** Every mutating CLI command can render and return the PNG path.
6. **Professional output.** 16-bit float layers, colour management, proper blend modes, exports a game engine can use as they are.
7. **Both hands can do everything.** Every feature has a CLI form (a command or an `apply` op) and an editor form (a tool, pane, window or command), doing the same thing through the same code. Only what makes sense on one side alone is exempt: the editor's view, pen calibration and keys; the CLI's batch, hash and test tools; and the ops that draw from shapes (`ink`, `light`, `hatch`, `paint`, `scatter`, `fill --shape`), which are how an agent draws what a person draws by hand.

## Architecture

```
crates/
  core     document model, ids, timeline, stroke format, bundle IO, op log
  brush    tile store, brush engine, stroke replay, checkpoints
  render   compositing, vector rendering, filters, overlays (Skia, CPU raster)
  cli      the `klad` binary, and `klad-editor`
  app      the editor, behind the `editor` feature (on by default)
```

Two binaries from one crate: `klad`, the command line, and `klad-editor`, the editor alone (a windowed program on Windows, the executable of `klad.app` on a Mac, started by the Linux AppImage). `klad open [bundle]` launches the same editor from the command line, on the bundle or, without one, on the start window (new, open, recent). `--no-default-features` builds `klad` without the editor. `klad --version` and the editor's About show the version and `git describe` of the commit it was built from (`crates/version.rs`, shared by both crates' build scripts; `KLAD_BUILD` overrides it).

**Platforms and packaging (M7).** Folders follow each platform: settings in `~/Library/Application Support/klad`, `%APPDATA%\klad` or `$XDG_CONFIG_HOME/klad`; downloaded fonts in the same places' data folder; drawings in `~/Drawings` by default. The open panel is `NSOpenPanel` on macOS and `rfd` elsewhere (the XDG portal on Linux, the common dialog on Windows). The pen: macOS reads `NSEvent`; elsewhere a pen that the system reports as a touch with force (Windows pens through `WM_POINTER`) draws with that pressure (`pen::from_egui`), and anything else draws as a mouse at full pressure; Linux tablets report no pressure through `winit` yet. `packaging/` makes the downloads: `macos/app.sh` builds `klad.app` (both binaries, lipo'd when several targets are given, the fonts, licences and skill in `Resources`, `.draw` declared as a document package of type `com.indicode.klad.drawing` so Finder shows a drawing as one item and opens it in klad) and a disk image; `archive.sh <target>` builds a `tar.gz` or `zip` with both binaries, `fonts/`, the licences and `SKILL.md`, and an AppImage on Linux when `APPIMAGETOOL` is set; `icon/` draws the icon in klad and packs `klad.icns` and `klad.ico`. Builds use the `dist` profile (no debug info, stripped, thin LTO); the samples hash the same from it. The fonts are found next to the binary (`fonts/`), in `../Resources/fonts` or `../share/klad/fonts`. On macOS a drawing opened from Finder arrives as an `application:openURLs:` message, which klad adds to `NSObject` before the event loop starts so it reaches whatever delegate `winit` installs; the paths queue up (`opened.rs`) and the start window or editor opens the last. `klad install` puts `klad` on the terminal's path (a link in `/usr/local/bin` through an administrator prompt on macOS, `~/.local/bin` on Linux, the user's `PATH` on Windows); the editor's document menu runs it as a job. `klad skill` prints the agent skill compiled into the binary. Builds are sold on itch.io (later Steam) for macOS and Windows, and Linux is built from source: on a version tag the `release` workflow builds the Windows version and pushes it to itch.io with butler (never as a workflow artifact, which anyone could download from a public repository) and publishes the changelog section as the release notes, and `just itch-mac` builds and pushes the Mac app from a Mac; `check` runs lint, tests and the audit on every pull request, tests on macOS and builds on Windows. The editor asks the GitHub releases API at most once a day (`updates.rs`, curl on a thread, off in the settings window) and, when a newer version is out, says so in the start window, the message line and About, with a link to what changed; it installs nothing.

### Determinism

The CLI render and the editor must agree. Rules for `core`, `brush` and `render`:

- Transcendental math (`pow`, `exp`, `sin`, `cos`, `atan2`) goes through the `libm` crate, never the platform libm.
- One seeded RNG type (`core::rng`), seeded per stroke. No wall clock in rendering.
- No `HashMap` iteration order affecting output. Tiles live in a fixed grid.
- Parallel work is split into independent units (tiles, image rows), each computed the same way regardless of thread count.
- `klad hash` prints a hash of rendered pixels; the parity check compares macOS and Linux.

## The document bundle

`docs/format.md` specifies everything below for other programs, byte by byte; this section is how klad itself uses it.

```
art.draw/
  doc.json                 canonical document (pretty JSON, stable key order)
  strokes/<layer>/<cel>.strokes   stroke and fill records per cel (binary, zstd)
  brushes/<id>.json        every brush the document uses, embedded on first use
  assets/                  imported images (PNG)
  .gitignore               ignores .cache/
  .cache/                  rebuildable: pixel tiles, checkpoints, renders, op log
```

Committed: everything except `.cache/`. A fresh clone rebuilds the cache by replaying strokes and fills.

### doc.json (format `draw-anything/9`)

```json
{
  "format": "draw-anything/7",
  "rev": 42,
  "canvas": { "width": 2048, "height": 2048, "background": "#f4efe6" },
  "timeline": { "fps": 12, "frames": 24, "origin": [1024, 1800],
    "clips": [{ "name": "run", "from": 0, "to": 11, "loop": true, "fps": 24 }, { "name": "jump", "from": 12, "to": 23 }] },
  "export": { "godot": "../game/art/hero" },
  "palette": [{ "color": "#1b1b1b", "name": "ink" }, { "color": "#f0c8a0", "name": "skin" }, { "color": "#5b6ee1" }],
  "layers": [
    { "id": "l3", "name": "lines", "kind": "paint", "opacity": 1, "blend": "normal", "visible": true,
      "cels": [
        { "id": "c1", "frame": 0, "hold": 2 },
        { "id": "c2", "frame": 2, "hold": 2 },
        { "id": "c3", "frame": 4, "hold": 2, "link": "c1" },
        { "id": "c9", "frame": 6, "hold": 1, "tween": { "from": "c2", "to": "c10", "t": 0.5, "made": "3f0c9e21a4b6d870" }, "parts": { "leaf": [14, 15] } },
        { "id": "c10", "frame": 7 }
      ] },
    { "id": "l5", "name": "shade", "kind": "paint", "blend": "multiply", "clip": true, "lockAlpha": true,
      "cels": [{ "id": "c6", "frame": 0 }],
      "mask": { "id": "l7", "name": "mask", "kind": "paint", "cels": [{ "id": "c8", "frame": 0 }] } },
    { "id": "g1", "name": "fx", "kind": "group", "opacity": 0.8, "blend": "screen", "visible": true,
      "children": [] },
    { "id": "l4", "name": "shapes", "kind": "vector", "opacity": 1, "blend": "normal", "visible": true,
      "cels": [{ "id": "c4", "frame": 0, "nodes": [
        { "id": "n5", "name": "sky", "type": "rect", "x": 0, "y": 0, "w": 2048, "h": 900,
          "fill": { "linear": { "from": [0, 0], "to": [0, 900], "stops": [[0, "#121d31"], [1, "#4a6a8c"]] } } },
        { "id": "n6", "type": "group", "transform": { "rotate": -8, "x": -120 }, "children": [
          { "id": "n7", "type": "path", "d": "M380 560 L560 560 L530 600 L410 600 Z", "fill": "#2b1d14",
            "stroke": { "paint": "#000000", "width": 3 } } ] }
      ] }] }
  ],
  "nextId": 7
}
```

- Layers are listed bottom to top. `ls` prints them top first, like a layers panel.
- Ids are unique across the document (letters, digits, `-`, `_`): new ones are `l`, `c` and `n` plus a counter.
- A **cel** is a layer's content from `frame` on. `hold` limits it to that many frames; without `hold` it lasts until the next cel. Drawing on twos is `hold: 2`. `link` reuses another cel's content; links cannot chain. Paint cels keep their strokes in `strokes/<layer>/<cel>.strokes`. In animation terms a cel that is not a link is a **drawing**, the frames it shows on are its **exposure**, and frames no cel covers are **blank**. The timeline (`frames`) always covers every cel's first frame: an op that puts a cel past the end makes the timeline longer, and a stroke, fill or shape added at a frame past the end starts a cel there instead of landing in the last open exposure.
- An **in-between** is a drawing made by `inbetween` from two keys: its cel keeps `tween` (format 6) with the keys' drawing ids (`from`, `to`), its position `t` between them (0 to 1, after spacing), how its marks were paired when not by id (`match`: `order` or `near`, and forced `pairs` as `[first key id, second key id]`) and `made`, a hash of the marks as they were made. `inbetween --redo` remakes in-betweens from their keys and refuses one whose marks no longer hash to `made` (drawn on or edited since) unless forced. A link cannot be an in-between; `set <cel> tween=null` makes it an ordinary drawing. `unpaired` (format 7) keeps how marks in one key only were shown (`pop`, `pop 0.3`, `fade`, `draw-on`), so a redo shows them the same way.
- A cel's **parts** (format 7) name groups of its marks: `"parts": {"leaf": [14, 15], "near leg": [9]}`. A mark is in one part at most. They live in the cel record, not in the stroke file, so naming parts never rewrites strokes; ids that no longer exist are ignored. `dup`, `unlink`, `copy` and in-betweens keep them (an in-between gets the first key's parts, as it keeps its ids). Format 6 documents open as format 7 without parts.
- A **clip** is a named frame range, both ends included: an animation such as `idle`, `run` or `attack`. It loops or plays once (`loop`), and may have its own `fps` (format 5); without one it plays at the timeline's. Names are unique and clips may overlap. Clips are kept in order of their first frame. Exports turn each clip into an engine animation. Frame ops on every layer move and stretch clips (an insert inside a clip lengthens it, a remove shortens it, a clip left with no frames goes); frame ops on listed layers leave them alone; a shorter timeline trims clips and refuses to cut one off entirely.
- The **origin** (`timeline.origin`, format 5) is the canvas point an engine export puts on the node's position, the centre of the canvas when absent.
- **`export.godot`** (format 5) is the folder Godot exports go to, relative to the folder holding the bundle, so the CLI and the editor's "export to Godot" button write to the same place.
- The **palette** is the document's colours, each with an optional unique name (not starting with `#`). Wherever an op or a CLI flag takes a colour for a stroke or a fill it also takes a palette name; the stroke or fill stores the colour itself, so renaming or recolouring a swatch never changes what is drawn.
- **Nodes** (vector cels): `rect` (x, y, w, h, radius), `ellipse` (cx, cy, rx, ry), `path` (SVG `d`), `group` (children). Each takes `fill`, `stroke`, `transform`, `opacity`, `blur` (Gaussian sigma in px, softens the whole node; when the blur reaches 12 device px or more the node is drawn 2 to 32 times smaller on a power-of-two grid aligned in device space, blurred there with an exact Gaussian in Rust and scaled back up, which is about 3 times faster than Skia's CPU blur and closer to a true Gaussian; non-uniformly scaled nodes keep Skia's blur), `clip` (an SVG path in the node's own coordinates that clips it and its children), `visible`, `name`.
- **Paint** is `"#rrggbb"`, `"#rrggbbaa"`, `"none"`, `{ "linear": { "from", "to", "stops" } }` or `{ "radial": { "center", "radius", "stops" } }`, in the node's own coordinates. As in SVG, a missing fill is black and a missing stroke is none. Strokes default to width 1 with round caps and joins; `dash` takes SVG-style intervals.
- **Transform** is `x`, `y`, `rotate` (degrees), `sx`, `sy`, `pivot`; it applies translate, then rotate and scale about the pivot, which defaults to the centre of the node's bounds.
- **Masks.** `mask` is a paint layer kept under the layer it masks, with its own id, cels and stroke files (`strokes/<mask id>/<cel>.strokes`). Its alpha hides the layer: strokes and fills on the mask hide, the eraser shows the layer again, and an empty mask (or a frame without a mask cel) hides nothing. `visible: false` turns the mask off. A mask keeps opacity 1 and blend normal and has no mask or clip of its own. Paint, vector and group layers can have one. Internally a mask's layer path ends in `MASK`, so `locate`, `layer_at` and the history treat it as a layer.
- **Clipping.** `clip: true` shows a layer only where its base, the nearest layer below it in the same list without `clip`, has alpha. The base and the clipped layers above it draw as one group: each clipped layer blends onto the base with its own blend and opacity (masked by the base's alpha), then the group composites onto what is below with the base's blend and opacity, as in Photoshop with "blend clipped layers as group". A hidden base hides its clipped layers; the lowest layer of a list draws unclipped.
- **Lock alpha.** `lockAlpha: true` on a paint layer makes new strokes and fills land only where the layer already has alpha: they composite source-atop and leave alpha unchanged. The flag is recorded on each stroke and fill (stroke format 5), so turning it off later never changes what was drawn. An eraser stroke on a lock-alpha layer changes nothing (the editor refuses it).
- `rev` increments on every write. Older formats are migrated on open (format, files, then the old files are removed); `/0` bundles from M0 upgrade this way. Format 2 (M2) changed no keys: it marks a bundle that embeds its brushes. `/1` bundles become `/2` by embedding the M1 version of every brush their strokes use (`crates/core/brushes/m1/`), so they render exactly as before. Format 3 (M2 batch 2) adds `palette` and marks a bundle whose paint cels may hold fills (stroke file version 4); `/2` bundles only change the format string, in memory until the next write. Format 4 (M2 batch 4) adds `mask`, `clip` and `lockAlpha`, and marks a bundle whose stroke files may be version 5; `/3` bundles only change the format string. Format 5 (M3 batch 3) adds a clip's `fps`, `timeline.origin` and `export.godot`; `/4` bundles only change the format string. Format 6 (M3 batch 4) adds a cel's `tween`; `/5` bundles only change the format string. History snapshots in older formats are migrated when undone.

### Edits

All edits are ops, applied as one transaction that either fully applies or changes nothing, and validated before anything is written. The CLI commands and `klad apply` (JSON lines) produce the same ops:

| Op | JSON line |
|---|---|
| add a layer | `{"op":"add","layer":{"kind":"vector","name":"sky"},"above":"l2"}` |
| add a node | `{"op":"add","node":{"type":"rect","x":0,"y":0,"w":10,"h":10},"in":"l4","frame":0}` |
| add a cel | `{"op":"add","cel":{"frame":4,"hold":2,"link":"c1"},"in":"l3"}` |
| set properties | `{"op":"set","id":"n5","fill":"#ff0000","transform.rotate":15,"stroke":null}` |
| remove | `{"op":"rm","ids":["n5","l3"]}` |
| move | `{"op":"mv","id":"l3","below":"l4"}` (or `in`, `index`) |
| paint a stroke | `{"op":"stroke","layer":"l3","brush":"ink","size":8,"color":"ink","path":"M0 0 L90 40","taper":[12,30]}` |
| fill | `{"op":"fill","layer":"l2","at":[820,640],"ref":"lines","gap":4,"color":"skin"}` or `"polygon":[[x,y],...]` |
| palette | `{"op":"palette","add":"#f0c8a0","name":"skin"}`, `{"op":"palette","rm":"skin"}`, `{"op":"palette","set":[...]}` |
| edit a stroke or fill | `{"op":"set","id":"c4:s12","color":"skin","size":6,"brush":"pencil"}`, `{"op":"rm","ids":["c4:s12"]}` |
| move, turn, scale marks | `{"op":"transform","ids":["c4:s3","c4:s5"],"x":40,"y":-10,"rotate":15,"sx":1.2,"sy":1.2,"pivot":[512,400]}` |
| path points | `{"op":"path","id":"n7","move":3,"to":[412,230]}`; also `"move":[3,4],"by":[dx,dy]`, `"handle":3,"out":[x,y]`, `"insert":3,"t":0.5`, `"add":[x,y]`, `"rm":[4,5]`, `"corner":2`, `"smooth":6`, `"simplify":1.5` |

| lasso | `{"op":"lasso","layer":"l3","polygon":[[x,y],...],"cut":true,"x":40,"y":-10,"rotate":15,"sx":-1,"pivot":[..]}` or `"rm":true` |

| clips | `{"op":"clip","add":"run","from":0,"to":11,"loop":true,"fps":24}`, `{"op":"clip","set":"run","name":"sprint","to":15,"loop":false,"fps":null}` (`null` fps: the document's), `{"op":"clip","rm":"run"}` |
| export folder | `{"op":"export","godot":"../game/art/hero"}` (`null` forgets it) |
| frames | `{"op":"frames","insert":4,"count":2}`, `{"op":"frames","remove":4,"count":2,"layers":["l3"]}` |

| in-betweens | `{"op":"inbetween","layers":["lines","colour"],"from":0,"to":6,"count":2,"spacing":"in-out","match":"near","pair":[[3,7]],"unpaired":"fade"}`, `{"op":"inbetween","layers":["lines"],"from":9,"loop":true}`, `{"op":"inbetween","redo":true,"keepDrawn":true}` or `"force":true` (computed by the CLI; alone in its batch) |

Unknown keys are errors that list the valid ones, so a typo never passes silently. Structure (`id`, `kind`, `type`, `cels`, `children`, `nodes`, `mask`) changes only through add, rm and mv; a mask cannot be moved, and nothing goes above or below it. A fill op needs pixels to compute its coverage, so the CLI computes it before the transaction, in op order: strokes and fills earlier in the same batch, and stroke edits, are part of what a fill sees.

**Frames and drawings.** `frames` insert puts `count` frames at a frame: what showed there now also shows on the inserted frames (the exposure covering it lengthens, a blank stays blank) and every later cel moves back. `frames` remove takes `count` frames out: exposures over them get shorter, later cels move forward, and a drawing left with no frames goes. Both work on every layer (then clips move with them and the timeline grows or shrinks) or on the listed layers and everything inside them (an insert lengthens the timeline only as far as their drawings need: a last drawing without a hold keeps its length, one with a hold must still fit; a remove leaves the length); a layer's mask always moves with it. Removing a drawing that links point to, by `rm` or by removing its frames, hands it to the first link: that link becomes the drawing (its strokes or nodes) and the other links point to it, so links never break. `cel` places a cel at `frame` on a layer: `new` a blank drawing, `dup` a new drawing with a copy of another's strokes and fills (mark ids kept, so a stroke in the copy is the same address in the new cel) or of its nodes (new node ids), `link` a link to another cel's drawing (a link to a link points to its source). Inside an exposure the new cel takes over the rest of it; on a blank frame it lasts until the next cel, or `hold` frames (`dup` and `link` default to their source's hold); `dup` and `link` default to the frame right after their source's exposure. With `insert` the layer's cels from that frame on move back by the new cel's length first (the timeline grows as for a listed-layer insert), which only works at the start or end of an exposure. `unlink` turns a link into a drawing of its own with a copy of its source. Copies of strokes are made when the batch is written, from the source as it is at that point of the batch.

**Copies.** `copy` copies strokes and fills (from one or more cels) into one drawing: `to` a cel, or the drawing a layer shows at `frame` (the marks' own layer unless `layer`; an empty frame or one past the end starts a drawing there; a frame showing a link names its source, which the editor resolves itself). The copies take the next ids of the target, keep their order (sources in the order given, marks in their source's order) and land on top; the op reports each `from` and `to` address. A move, turn, scale or flip applies to the copies together, about `pivot` or the middle of their bounds. `cut` adds a cut keeping the inside of a polygon to every copy, so only the parts inside are seen. Copies see the batch as it is at that point, like `dup`.

**Retiming.** `retime` takes frames `from` to `to` (both included) on every layer, or on the listed layers with their masks and children. The range is cut into pieces where any of those layers changes what it shows, so layers stay in step; each piece is one picture. `on n` gives every piece n frames; `fit n` makes the range n frames, each piece starting at its old position scaled (rounded, at least one frame each, order kept; fewer frames than pieces is refused); `reverse` plays the pieces backwards; `pingpong` adds them again backwards without repeating the ends (a b c d c b). Every affected layer is rebuilt from what it shows frame by frame: runs of the same drawing merge, a drawing's first run keeps the cel (and its hold style), later runs become links to it. Everything after the range moves by the change in length. On every layer, clips move and stretch with it (an end inside the range is scaled with the range) and the timeline grows or shrinks; on listed layers clips stay and the timeline only grows, as for a frame insert.

**In-betweens.** `inbetween` makes drawings between two keys on paint layers: the drawings shown at `from` and at `to` (where the second key's exposure starts; a link there names its source, so a loop's last in-betweens lead back to its first drawing). By default a cel goes on every frame between them; with `count` n they go on frames spread evenly between the keys, each held until the next, and the first key's exposure ends at the first one. Positions follow `spacing`: `even` (i/(n+1)), `in` (squared: bunched near the first key), `out` (bunched near the second), `in-out` (smoothstep), or the positions themselves. Cels already between the keys must be in-betweens of the same keys (they are replaced) unless forced. A layer that shows the same drawing at both keys is left alone. The CLI computes the marks, then the op adds the cels and their marks as one history step.
- Pairing: by id (default: a key duplicated from the other keeps its ids), by `order` (strokes, lasso fills and flood fills each in order) or `near` (greedy on the mean distance between 16 points along each, trying a stroke backwards too). `pair` forces pairs first. A stroke never pairs with a fill, nor a lasso fill with a flood fill; unpaired marks are left out and listed.
- Each stroke pair is resampled by arc length to the longer one's sample count; pressure, tilt and time ride along. The best-fit rotation and scale from the first key's points to the second's (a similarity, least squares) is followed along its arc: about its fixed point, the angle and the log of the scale moving with t, and what the fit leaves is added on top in proportion. So a swinging stroke turns about the point it swings around and keeps its length.
- Strokes ride on the lines they touch: a stroke end that touches another stroke in both keys (within half that stroke's size plus 2 px, plus a quarter of its own) joins them in a tree rooted at the longest stroke of each connected group, and a child moves in its parent's frame: the parent's motion at t, then the child's own turn relative to the parent along its arc. A hand bending at the wrist stays on the turning arm. The touching end is then moved onto the other line at the interpolated contact (its place along that line and its offset, both interpolated), pulling the nearest third of the stroke (up to 48 px) with it, so closed shapes stay closed. On a closed line, the second key's contact is the one nearest along the line to the first key's, and a contact that jumps more than half the line is not kept.
- Size, opacity, flow, taper and colour interpolate (colour in OKLab, so lightness and hue change evenly; keys of one colour keep it exactly), so light can follow a turning limb when the second key is coloured for it; brush, seed, lock alpha and cuts come from the first key (cuts move with the stroke); in-between marks keep the first key's ids and are marked agent.
- Lasso fills interpolate their polygons the same way. Flood fills are recomputed in each in-between: the seed is carried by the lines it sits next to (the nearest point on the nearest paired stroke of the reference, its place along that stroke and its offset across, found in each key, placed on the in-between strokes and blended by t), moved onto the nearest open pixel when it lands on a line, and the fill is computed with its own settings against the in-between's reference. Layers whose fills reference another in-betweened layer go after it, `all` last. A fill that lands on a line, covers nothing, or comes out over 1.6 times (plus 64 px) or under 0.4 times what the keys' areas say is left out and listed.

**Fills like another drawing.** A `fill` with `like` carries every flood fill of one drawing to the layer's other drawings on `frames` (all, a range or a clip): for each target, the reference at the frame where it first shows is cut into regions as the fill would see them (its colour, tolerance and gap); each region near the old fill is compared with the old coverage shifted onto the region's centre (overlap over union, falling off with the distance moved), regions open to the canvas edge only when the old fill touched it; the seed goes to the best region's pixel nearest the shifted old seed and the fill is computed there. A target that already has a fill with that id has it replaced in place, otherwise the fill goes on top with that id (or the next free one). Fills that find no region, cover nothing or come out over 2.5 times (plus 256 px) the old one are listed. One history step for all targets.

**Parts, arcs and hand work in in-betweens (M4.5 batch 2).** Pairing for in-betweens goes forced pairs first (`--pair`), then part by part for every part name both keys have (within a part and a kind of mark, in drawing order when the counts match, by nearest shape when they do not), then the `match` rule for the rest, so keys drawn separately pair whatever their ids. `--loop` takes the loop's first drawing as the second key (the clip holding `--from`, else frame 0; `--to` defaults to the loop's end), so a cycle closes without a temporary link. Marks in one key only follow `unpaired`: left out (the default, listed), `pop` at the middle or at `t`, `fade` (opacity over the in-betweens), `draw-on` (drawn along their length; one-key marks of the first key draw off); they are carried with the lines around them (`tween::carry`: every point anchored along the nearest paired line and placed on that line in the in-between), and flood fills among them are still left out. `--redo --keep-drawn` splits an in-between's marks by author: it remakes the agent's from the keys and keeps the hand-drawn ones on top, carried from the old in-between's lines to the new ones (aligned by mark id; a hand mark in a part follows the lines of that part), with new ids and their parts; `made` stays the hash of the agent's marks, so a plain `--redo` still refuses it. Arcs (`cli/src/arcs.rs`) track a mark through the drawings that show its id, a part's centre in each drawing of a layer (the first paint layer that has the part, or `layer:part`), or a point carried by the stroke nearest to it at the first frame; each frame gives a centre, a lowest point (the middle of the samples within 1 px of the lowest y) and the sole (the span of the samples within 2 px of it, the part on the ground). `--ground` reports the lowest point under the line, and slides: consecutive changed positions both on the line (within `--slack`) where neither end of the sole nor its lowest point moved by `-travel` per frame (a cycle drawn in place should move a planted foot back by the travel); the slide is the smallest of those three moves, so a foot rolling from heel to toe, which keeps one end still, or turning a little on its lowest point, is not a slide, and a foot pushed along the ground, which moves all three, is; with two tracks, frames where their left-right order flips are swaps. `--overlay arcs` draws each track as a line with a dot and a tick across the path per frame, numbered, the current frame ringed; `--overlay parts` boxes and names each part.

**Drawing from shapes.** `ink`, `light`, `hatch`, `scatter` and `fill` with `shape` read the outlines of vector shapes (rects, ellipses, paths; a group means each shape in it), flattened every 2 px and taken to canvas coordinates through the node's transforms (`klad_render::shapes`), and are turned by the CLI into ordinary strokes and fills before the transaction (`cli/src/shapes.rs`), so they replay like any mark; shapes added earlier in the same batch are seen. Ink resamples each outline, splits it at corners sharper than `break` degrees (open paths at their ends too), and gives each sample a pressure from three rules multiplied together and smoothed: the outward normal against the light (0.55 facing it to 1 facing away), the silhouette (0.7 where the outline lies inside another closed outline of the call), the curvature (down to 0.65 on tight curves); a seeded two-sine wobble moves points along the normal. A closed outline without corners is one stroke that starts at its lightest point and overlaps its start by 12 px. `light` makes lasso fills of each closed outline with a cut that keeps the outside of the same outline moved towards the light by `depth` (in `soft` steps from 0.6 to 1.4 times the depth, each at a share of the opacity) for the shade, and moved away from the light by `rimWidth` for the rim. `hatch` cuts parallel lines (or inward offsets of the outline with `along`) into pieces of the given lengths, jittered and clipped to the area; `scatter` places a mark at jittered grid points or `count` random points inside the area and outside `avoid`, scaled and turned by seeded amounts. All of it is deterministic (libm, the seeded RNG). Lasso fills skip the CLI's catch-up of earlier marks (only flood fills need to see them), so 160 fills from one `light` of 40 shapes take about 260 ms.

**Stroke addresses.** Strokes and fills are addressed as `<cel>:s<id>`, for example `c4:s12`; fills share the id counter with strokes. `set` on a stroke takes `color`, `size`, `opacity`, `flow`, `brush` and `taper`, on a fill `color` and `opacity`; colours may be palette names. `transform` applies translate, then rotate (degrees, clockwise) and scale about `pivot`, by default the middle of the marks' bounds; stroke samples move at their stored 1/16 px precision, sizes and tapers scale by the square root of the area scale, tilt turns with the stroke, and fills move by whole pixels (their coverage shifts exactly) or are resampled bilinearly when turned or scaled. Marks keep their ids and their place in the order. Ids in several cels need an explicit pivot.

**Lasso.** A `lasso` op works on the strokes and fills of one paint cel inside a polygon. A stroke is inside when every sample it keeps (see cuts) is inside the polygon, a fill when every pixel it covers is; marks with some of each cross the edge. Without `cut` the op moves, turns, scales, flips (negative `sx` or `sy`) or removes (`"rm":true`) the marks inside. With `cut`, every crossing mark is first split in two: the original gains a cut that keeps the outside of the polygon and stays where it is, and a copy with a new id, placed right after it, gains a cut that keeps the inside and moves with the rest. So nothing outside the lasso changes, and the moved parts stay strokes (recolour them, thin them, move them again). The op is one history step and reports the ids it moved.

**Cuts.** A stroke or fill may carry cuts: polygons with a side to keep (`inside` or `outside`). When the mark is painted, its coverage is multiplied by each cut's coverage of the polygon (4x4 supersampled, even-odd) or one minus it; tiles a cut leaves untouched are skipped. Cuts move, turn and scale with their mark. A split stroke drawn in place shows a faint seam only where the lasso edge crosses its antialiased edge, the same as a raster cut and paste. A cut is not a layer mask: it belongs to the mark and replays with it.

**Path points.** A path, rect or ellipse reads as subpaths of anchors, each with an in and an out handle (absolute, in the shape's own coordinates; a handle on its anchor means none). Every SVG command parses into this form (quadratics become cubics exactly, arcs become cubics of at most 90 degrees) and is written back as `M`, `L`, `C` and `Z` with two decimals. A rect or ellipse becomes a path that looks the same on its first point edit. Anchors are numbered across subpaths. Smooth means both handles present and in line; moving one handle of a smooth point turns the other to stay in line unless `free`. `insert` splits a segment at `t` without changing its curve, `add` finds the nearest segment, `rm` joins the neighbours, `corner` drops the handles, `smooth` sets them along the line between the neighbours at a third of each distance, and `simplify` refits each run between sharp corners (over about 50 degrees) as least-squares cubics (Schneider) within the tolerance, keeping straight runs straight. Before a path op, the CLI and editor pin `transform.pivot` on the shape and every group above it whose transform is not identity and has no pivot, so a point edit never moves the rest of the shape.

### Layer kinds

| Kind | Content | Mostly made by |
|---|---|---|
| `paint` | strokes, replayed to f16 tiles | human pen, agent scripted strokes |
| `vector` | shapes, paths, text, generators | agent |
| `pixel` | palette-indexed grid, no anti-aliasing | agent and human |
| `adjust` | one adjustment: `hsl`, `levels`, `curves`, `balance`, `gradient-map`, `fill` (M5) | either |
| `group` | children, blend mode, opacity, mask, clipping | either |

Every layer has `blend`, `opacity`, `visible`, `locked`, optional `mask`, `clip` and (M5, format 8) `effects`. Effects are layer settings, not a layer kind: the planned `filter` kind became them.

- **Blend modes.** `normal`, `multiply`, `screen`, `overlay`, `add`, and since M5 `color-dodge`, `soft-light`, `hard-light`, `lighten`, `darken`, `color`, `luminosity`, all as in the W3C compositing spec (Skia's modes; `look::blend_rgb` and `look::composite` hold the formulas the tests check them against).
- **Effects (M5).** `"effects": [{"glow": {...}}, {"outline": {...}}]`, applied in order to the layer's content (after its mask; for a clip base, to the base and its clipped layers together) before its opacity and blend: `blur` (radius, a Gaussian sigma), `glow` (radius, strength, threshold: 0 glows from every pixel, higher only from the bright ones; color: a tint; blend: how the glow mixes with what is under the layer, screen by default, normal lays it like paint under the layer), `outline` (width, color, inside), `shadow` (x, y, radius, color, laid under the layer), `noise` (amount, size, seed, mono: a grain fixed to the canvas), `displace` (amount, size, seed, by: smooth waves, or a layer whose red pushes across and green down), `relief` (strength, light, highlight, shade, softness: lights the paint height of the layer's drawings, below). Each effect knows its reach (`look::reach`), so a tile is composed from its content within the tile plus that margin and tiles meet without seams; the pixels are computed in Rust (`klad-render/effects.rs`) on f32 with absolute coordinates, so a tile equals the same pixels of the whole image byte for byte (tested). Blurs use a direct kernel, below a sigma of 2 at full size and above it on a grid of 2, 4, ... px blocks anchored to the canvas, then sampled back.
- **Adjustment layers (M5).** An `adjust` layer changes what is under it in its list: the layers below it in its group, or, clipped, its base. A group holding an adjustment is composed apart, so the adjustment stays inside it. The colour math is on unpremultiplied sRGB values with alpha kept: `hsl` (hue in degrees, saturation and lightness -1..1), `levels` (black, white, gamma, low, high), `curves` (points, and red, green, blue applied before them; monotone cubic, no overshoot), `balance` (shadows, midtones, highlights: cyan to red, magenta to green, yellow to blue, keepLight), `gradient-map` (stops by brightness). The layer's opacity, blend and mask decide how much of the adjusted colour replaces the colour under it. `fill` (a solid or gradient paint) is drawn like a content layer instead, with the layer's blend.
- **Rays (M5).** A vector node `{"type": "rays", "x", "y", "angle", "spread", "count", "length", "start", "falloff", "noise", "seed"}` draws soft beams from an origin (a gap `start` px wide), each a quad with a radial falloff and its own length and strength from the seed; the node's `fill` colours them and its `blur` softens them. Rays come from the agent (`klad add rays`); in the editor a selected rays node shows its settings in the inspector.
- **Depth and atmosphere (M5).** A layer at the top of the stack (a plane, usually a group) may have a `depth` (0 is near; validation refuses it deeper in the tree). The document's `atmosphere` (`color`, an optional `top` colour blended down over the canvas height, `density`, `blur`, `desaturate`) turns each plane's depth into two effects after its own (`Document::effects_of`): a `haze` towards the fog of `1 - e^(-density x depth)` with `desaturate x depth` of its colour taken out, and a blur of `blur x depth` px. `haze` is an ordinary effect too. The depths are kept for M6's Parallax2D export; in the editor a depth field sits in each plane's row and inspector, the inspector holds the atmosphere, and holding D shows the planes (each flattened alone, in the background) sliding by `offset x 0.08 / (1 + depth)` with the pointer.
- **References (M5).** Any layer can be `reference: true`: the editor shows it, renders, hashes and exports leave it out unless asked (`--references`), and fills never see it.
- **Pictures (M5).** A picture is a vector node `{"type": "image", "src", "x", "y", "w", "h"}`, so V moves and scales it and the inspector fades it. Importing (`klad add layer image src=photo.jpg`, dropping a PNG or JPEG on the editor, or "import a picture") decodes PNG with `png` or JPEG with `zune-jpeg`, re-encodes it as PNG and stores it as `images/<content hash>.png`, so the same file twice is stored once and every machine draws the same pixels; it lands on a new vector layer, fitted inside the canvas. The renderer finds pictures and fonts in the folders of every bundle the process opened (`klad_render::assets`).
- **Generators (M5).** `scatter` (copies of its children over a region, `count`, `seed`, `size` and `turn` ranges, `avoid`: SVG paths no copy's centre may fall in), `repeat` (`count` copies, each `step` further, turning `turn` degrees and growing `scale` about `pivot`, or a grid `columns` wide with `row` between rows) and `mirror` (its children and their reflection across a line through `x, y` at `angle`) are nodes whose children are drawn once per instance (`generators.rs`); they stay settings, the inspector edits them, and "repeat it", "scatter it", "mirror it" put a selected shape inside one; "take the shapes out" removes one and keeps its shapes where its first copy was. Their children keep their ids, so V can still pick inside.
- **Text (M5).** `{"type": "text", "text", "font", "x", "y", "size", "tracking", "leading", "align", "weight"}` with the node's fill and outline. The font is a file in the bundle's `fonts/` folder, so a drawing renders the same anywhere. Each line is shaped by `harfrust` (HarfBuzz's shaping in Rust: GPOS and `kern` kerning, ligatures, marks, scripts), `weight` sets a variable font's `wght` axis, and the outlines come from the file through `skrifa`, each glyph's contours merged with Skia's path ops so an outline never shows the overlaps variable fonts are built with; they are drawn as one path, never by the system's font engine, so the Mac and the container draw the same pixels. A missing font is refused with its name.
- **Fonts (M5, S5.26).** klad ships about fifty open families for game art in `fonts/` (sans, serif, mono, display, handwriting, pixel; OFL-1.1 or Apache-2.0, unchanged from the Google Fonts repository at a pinned commit, listed with their licences in the notices; `fonts/update.py` fetches them again). `klad_render::fonts` finds that folder next to the binary (also `../Resources/fonts` in a Mac app and the repository's `fonts/` for development builds; `KLAD_FONTS` overrides), and keeps families downloaded on request in a per-user folder (`~/Library/Application Support/klad/fonts`, `$XDG_DATA_HOME/klad/fonts`, `%APPDATA%\klad\fonts`). `fonts/catalogue.json` lists every open family on Google Fonts (about 1,900) with its group and folder at the same commit, so `klad fonts --search` works offline and a download (`klad fonts --get`, or naming a family anywhere a font is taken) fetches exactly that commit's files with `curl`. Choosing a font anywhere (the CLI's `font=`, `klad font`, the editor's picker) copies the file and its licence into the bundle; the node keeps the file name. This replaces M5 choice 3 (no fonts with the app). The editor's frame and plane caches fold `klad_render::RENDER_VERSION` into their keys, so pictures cached before a renderer change are not shown again. A light layer is no kind of its own: a paint layer set to `add` with a soft glow (a shortcut button for it only confused the layers pane).
- **Foliage (M5, S5.27).** `foliage` is a shape op (CLI only, principle 7): each closed shape becomes a clump built from leaf strokes on a jittered grid, each coloured from the clump lit as a round form (a normal from its bounding ellipse, mixed with the normal of an optional `mass` shape so clumps turn with the whole crown, a key light or a lamp, the underside darker) and stepped into three value families between `shade`, `color` and `lit` (OKLab; by default darker and cooler, lighter and warmer), with more variety in the light; then leaves along the outline, kept more where the outline faces the light or the sky, a few in `glow` on the shadow edge. Strokes are sorted dark to light so lit leaves land on top. It puts how foliage is painted (light families on the clump, the big mass before the texture, a broken silhouette) into one op, so an agent does not scatter leaves like confetti.
- **The agent in the editor (M8).** The Agent pane (closed until asked for; `agent panel` in cmd K or the panels menu) runs a model with four tools over the same surface a terminal agent has (`app/src/agent`): `look` renders the drawing (`klad render`, the longest side fitted in 1024 px unless a region or scale is given) and returns the PNG as an image in the tool result; `read` returns the selection, notes, layer tree, a layer's strokes, frames, bones or keys; `klad` runs any subcommand with the drawing's path put after it, refusing `open`, `install`, `watch`, `bench`, `demo`, `stress`, `scribble`, `new` and `apply` and any argument that looks like a path outside the drawing or the `exports` folder next to it (lexically normalised, no `~`); `apply` takes op lines. With "may edit" off for a drawing (kept per drawing in settings), only `look` and `read` are offered. The turn loop (`agent::turn`) runs on a thread behind a `Provider` trait: it sends the history, streams text and progress notes to the pane, runs every tool call of a reply in order and returns all their results in one user message, stops at the next tool call when Stop is pressed, and refuses to start a request once the session's estimated cost reaches the spend limit. Each turn counts its edits; "undo this turn" steps the shared history back that many times. The user's message carries the selection and pinned notes. The Claude provider (`agent/claude.rs`) is raw HTTP through `curl` (no SDK for Rust): `POST /v1/messages` with `anthropic-version: 2026-10-21`, streaming SSE (text, thinking, signature and tool-input deltas assembled into whole blocks that go back unchanged, a tool input that does not parse is answered as an error instead of being run), `claude-opus-5-5` by default at effort medium, adaptive thinking with `display: "updates"` for progress notes, server-side `fallbacks: "default"` on the models that take it, `cache_control` on the system prompt (the agent skill) and the last tool plus automatic caching of the conversation, and `GET /v1/models` for the model list. The key never reaches the command line: curl reads its headers from stdin (`--config -`), the request body goes through a temporary file. The key is kept in the macOS Keychain (`security -i`, fed on stdin) or, elsewhere, in a file in the settings folder only its owner can read; never in settings, the drawing or a log. A notice says once what is sent. Tokens and an estimated cost show per turn and per session. A scripted provider drives the tests. "Report a problem" (document menu) copies the version, the system, the drawing's size and the last 40 messages, without its path.
- **Rigs (M6).** A paint layer or a group gets `bones` (format 9): each a name, an optional parent that comes before it, a head and a tail in canvas px. A group's skeleton poses every paint layer in it together, so a character's lines, colour and shading layers stay in step. Each bone has a weight map in `weights/<owner>.weights` (zstd: a JSON header with the grid size and bone names, then one byte per cell per bone, cells of 4 px), written by `Bundle::apply` with the edit and kept in its history step; weights are normalised across bones when read (bilinear between cells), and a place no bone weighs follows the nearest bone. Automatic weights are 1/(d + 0.15 L + 1)^3 by distance to each bone segment (L its length), so joints blend over a short stretch; `set` paints soft dabs (smoothstep falloff towards a value), `part` gives a named part's cells to one bone at 1 and the others 0, `smooth` blurs every map once. A pose (`pose` on a cel: its rest drawing's id, an angle per bone in degrees from rest, a root move) is linear blend skinning: each bone's rest matrix (head, angle) and posed matrix (its parent's posed matrix times the rest offset times its turn) give a skin matrix, and every stroke sample moves by the weighted sum; stroke sizes scale by the mean local stretch (the Jacobian's determinant, square-rooted); polygon fills move their points; flood fills are warped through a 4 px triangle mesh over their coverage (each posed triangle rasterised, sampling the rest coverage by barycentric position). The rest pose returns the marks untouched. `pose` (computed by the CLI, `cli/src/rig.rs`) makes or re-poses a drawing at `to` on every paint layer under the skeleton from the rest drawing shown at `from` (a posed drawing's own rest when `from` shows one). In-betweens of two poses of one rest drawing (or a pose and its rest) mix the angles and root by t instead of matching strokes (`rig::posed_pair`), and keep the mixed pose. The editor's bone tool (J) draws bones (from a bone's end makes a child), picks, renames and removes them, paints weights in its own process (`klad_core::rig::weights_for`) over a tint of the picked bone's map, and turns bones in pose mode, committing the pose through `klad pose` as a job; the drawing is not deformed live while turning, only the skeleton.
- **Keys (M6, S6.5).** Layers, groups and vector nodes keep `keys`: per property (`x`, `y`, `rotate`, `sx`, `sy`, `opacity`) a sorted list of frame, value and ease (linear, in, out, in-out, step, or a cubic curve x1,y1,x2,y2 solved by bisection). A segment follows its first key's ease; values hold before the first key and after the last. Layers and groups composite with their keyed opacity and, when moved, with their keyed transform about the canvas centre (drawn whole, not tile by tile, while moved); nodes take keyed transforms and opacity when rasterised (`nodes_at`). The editor's frame and plane caches hash the keyed values; its vector raster cache does not follow node keys yet, so keyed shapes move in `klad render` and the exports, not in the editor.
- **Godot scenes (M6, S6.6, S6.7).** `export --godot-scene` flattens each visible top-level layer (with its fog; the background with the first) into a texture on a `Parallax2D` with `scroll_scale` 1/(1 + depth), the factor the editor's depth preview (hold D) uses. `export --godot-rig` writes per skeleton: each part of the rest drawing (named parts of each paint layer's rest drawing, the loose marks as one) replayed alone, trimmed, on a `Polygon2D` with a 16 px triangle mesh over its pixels (one cell of margin), UVs, and per-vertex weights sampled from the maps; a `Skeleton2D` with a `Bone2D` per bone at rest (local position and angle against the parent, `rest`, `length`); and an `AnimationPlayer` with one animation per clip (or one for the timeline) whose value tracks hold each bone's rest angle plus its pose at the frame each posed drawing starts (stepped, so drawings hold as in klad); frames that are not poses of the rest drawing are listed for the frames export. Re-exports keep their uids. `samples/rig` builds a figure with all of it.
- **Paint over (M5, S5.29).** `paintover` (`cli/src/paintover.rs`, resolved before the shape ops, alone in its batch) flattens the source (the `from` layers, or every visible layer below the target's top-level layer with the background) into OKLab, then follows Hertzmann's painterly method: for each brush size, biggest first, the source is blurred to that size, a grid at half the size finds cells whose mean difference from the painting so far (an estimate made by stamping discs of each stroke's colour) exceeds `threshold`, and a stroke starts at each such cell's worst pixel in a seeded random order. A stroke walks in steps of half its size across the luminance gradient (Sobel), turning towards it by `curve` times how sure the gradient is (weak gradients keep the stroke's direction; with none, a smooth seeded field of mostly level angles), and stops past its minimum length when the source there is closer to the painting than to the stroke's colour, at a colour change over twice the threshold, at the edge of the region or at its maximum length. `focus` keeps the last size to a shape grown by three of those sizes. Each stroke becomes a stroke op with a press-in and lift-off pressure, its size a little varied, its colour broken by `vary` from a hash of its seed, in the part `part`. `like <cel>` carries a paint-over to another drawing: every source paint layer's two drawings are paired as in-betweens pair them; each stroke rides the topmost source mark under its centre (a stroke within half its size, a polygon fill, a flood fill's coverage) with `tween::carry` along that mark's line (still marks: it stays; marks gone: it fades to opacity 0); it keeps its seed and is recoloured from the new source at its start, faded when it would now cross an edge; new strokes, in `<part> added`, only go where the source changed (its colour or alpha, grown by the biggest size) or where carried strokes left a gap. `--frames a-b` repeats that drawing to drawing, making a drawing on the target wherever a source layer starts one (a link where they link). `samples/paintover` paints over the lemons and carries a paint-over through the creature's walk; frame to frame its background changes by 0.03 of 255 on average.
- **Compare (M5, S5.30).** `compare` (`cli/src/compare.rs`) renders the drawing at the reference's width (or reads a PNG or JPEG), resamples it to the reference's size, composites both over white and compares in OKLab: L at the 5th, 50th and 95th percentile, mean chroma, texture as the mean absolute Laplacian of L, sharpness as the 99th percentile of the gradient, and the mean difference, each x100; per `--region` the mean colours and their difference; words when a difference passes a threshold (2 L, 1.5 in a or b, 10% chroma, 20% texture, 15% sharpness); `--heat` writes the per-pixel difference as black to red to yellow to white at 20. The editor's "compare with the reference" runs it as a job against the first picture on a reference layer and shows the numbers and the heat in a window.
- **Grass (M5, S5.28).** `grass` is a shape op too: rows of blades from the far (top) edge of the shapes to the near one, scaled from `far` to 1 by depth, leaning by `wind` with a bend, each from a dark root (`color`) to a lit tip (`second`, the `blade` brush blends to it by pressure as the blade thins) over ground that rolls in a value noise foreshortened with depth, lit by the light or lamp in soft value families; taller blades root just inside the top edge and break it; lit blades get a thin glint on their lit side; strokes are sorted far to near. Each root picks a species (`kinds`, by default fine, broad, dry, seed heads and clover) weighted by its share and by a noise of its own, so species grow in patches; heads and low plants thin out with distance. Per blade the hue, chroma and taper vary. A picture brush gets one stamp per blade; a species with a `head` gets a picture stamped at its tip; `low` species are stamped near the root and drawn before the blades around them. Both ops take any brush: they place and light marks, the brush (often the agent's own pictures) gives them their look.
- **Picture brushes start facing the stroke (engine version 6).** A brush whose angle follows the stroke places its first dab before it knows the stroke's direction, so that dab points right. For a picture tip that made one-dab marks (a leaf, a tuft) never turn; such a brush now holds its first dab until the second point gives the direction (a tap is drawn when the stroke ends, `StrokePainter::end`, called by the replay and by the editor at pen up), the same live and in replay. Round, chalk and bristle tips keep the old first dab, so M1 drawings and every painted sample render as before; only strokes with picture tips and a following angle (`leaves`) change.

## Strokes

### Recording

Pen samples are quantised the moment they arrive, and the brush draws from the quantised values, so a replay matches what was drawn exactly. Before quantising, the editor passes each sample through:

1. **The pen's calibration curve**: lightest and heaviest raw pressure and a gamma, kept per pen device in the user's settings (`~/Library/Application Support/draw-anything/settings.json`, `$KLAD_SETTINGS` overrides). A touching pen never records below one pressure step, so 0 keeps meaning "no reading".
2. **The brush's pressure smoothing**: an exponential average with a time constant in ms.
3. **The brush's stabiliser**: the position is the average of the raw positions of the last N ms. At pen up the window drains, so the line catches up to where the pen lifted.

Stored pressure is therefore device independent and replays need none of these settings. Mouse and trackpad samples that carry no pressure (a tap-drag) record 1; a stroke whose pressure is 0 on every sample draws as if pressure were 1.

| Channel | Stored as |
|---|---|
| x, y | 1/16 px, zigzag varint delta |
| pressure | 12 bit, zigzag varint delta |
| tilt x, y | 8 bit each (-1..1), delta |
| time | ms since previous sample, varint |

A stroke header holds the stroke id, brush id, colour, base size, opacity, flow, seed, author, the channel mask and, when set, the taper (in and out lengths in px; stroke format 3, M2), then (stroke format 5, M2 batch 4) the lock alpha bit in the channel mask and, when the mark has cuts, the cuts. Fills carry the same two in the high bits of their source byte; a stroke or fill without them encodes byte for byte as in format 4. Samples are stored per channel (all x deltas, then all y deltas, ...) so zstd compresses them well. One file per cel. Since stroke format 4 (M2 batch 2) every record starts with a kind byte, stroke or fill, and strokes and fills share one id counter per cel; files of versions 1 to 3 hold strokes only and still load.

### Size budget

Estimate before M0: about 0.5 KB per stroke, so 10,000 strokes is about 5 MB. A fully painted 4096x4096 f16 layer is 128 MB uncompressed. Strokes are the small part; pixels live in the gitignored cache. M0 measures the real numbers.

### Fills

A fill is a record in a paint cel, in order with the strokes: id, colour, opacity, author, how it was made, and the coverage it produced (a crop box and 8-bit alpha, run-length coded, then zstd with the rest of the file). Replay paints the stored coverage like a stroke buffer at full flow, so a fill never depends on other layers or on the fill code: CLI and editor, macOS and Linux get the same pixels.

- **Flood fill** (`at`): pixels count as inside when every premultiplied channel is within `tolerance` (0 to 1, default 0.1) of the seed pixel in the **reference**: `this` layer as it was just before the fill (its earlier marks), a named layer (paint, vector or group, drawn alone at full opacity, even when hidden) or `all` (everything visible over the background). Four-connected.
- **Gap closing** (`gap`, px): the lines are grown by `(gap + 1) / 2`, so openings up to `gap` px wide close and the open space splits into free regions; the fill takes the seed's region (a click near a line starts from the nearest free region). The pixels the growth took from the open space go to whichever region reaches them first along paths that stay off the lines (chamfer distance, ties to this fill), so the fill reaches into corners and sharp points, two fills that meet in a gap meet on a line across it, and a fill never escapes through a gap it closed. Islands of free space with no pixel 2 px clear of the grown lines do not count as regions. Where a fill that grows under the lines (`expand` above 0) ends in open space (across a gap, or at its tolerance), the pixels just outside it get a feathered edge from the fill's 3x3 neighbourhood (at most half cover), so a diagonal edge across a gap is smooth instead of a staircase and two fills meeting in a gap blend into each other with no seam; edges under the lines stay as they were.
- **Expand** (`expand`, px, default 2): the result grows that far into line pixels only, under the line's anti-aliased edge, so no paper shows between line and colour.
- **Lasso fill** (`polygon`): the polygon's area with 4x4 supersampled edges, nonzero winding.
- **Gaps**: `klad gaps` cuts a fill layer's reference into closed regions (as a flood fill with the layer's gap would, one pixel further from the lines) and lists those no fill of the layer covers: pockets a fill missed, or drawings not coloured yet. Regions open to the canvas edge are the outside and do not count; smaller than `--min` px (12) are ignored. The reference, gap and tolerance default to the layer's flood fills on those frames.
- **Refill**: `klad refill` recomputes the coverage of every flood fill in a cel (or one, `--id`) from its stored seed and settings against the current reference, keeping its place in the order.
- Speed (container): a 2048x2048 flood fill takes about 30 ms, 55 to 65 ms with gap closing; a whole `klad fill` on a 2048 canvas, loading the reference from cached tiles, 80 to 110 ms. Fills are deterministic on any thread count.

### Replay and checkpoints

A layer cel's pixels are its strokes and fills replayed in order. Each replay records every mark's footprint (the tiles it touched) and its key (id and a hash of its encoded record), and keeps a checkpoint every 128 marks: the tiles as they were at that point, shared with the previous checkpoint where they did not change. Checkpoints are capped at 128 MB per cel by thinning out every other one.

A stroke lands on its tiles only inside the rectangle its dabs wrote in each tile, and only that rectangle is cleared after it, so a small mark on a large tile costs its own area. Where no mark on a cel reads pixels (no wet, smudge or blender), the CLI replays a cel tile by tile on every core (`CelReplay::replay_tiled`): each mark goes to the tiles its samples' bounds reach (padded by the brush's largest dab and its scatter), each tile replays its marks in order with the others masked out, and the tiles are put together. Every mark's real footprint is then checked against the guess; if any mark reached a tile it was not sent to, the cel replays in order instead, so the pixels are always a full replay's. The tiled replay keeps no checkpoints beyond the first; the editor replays in order, since it edits cels and wants them. A 960x480 still of 41,731 strokes (about 2 million dabs) takes 0.85 s instead of 4.8 s in the container (`klad bench`, the `still` line).

When the marks change (an edit, a removal, an undo, an insert), the old and new lists are matched by key. Marks that kept their key and their order stay; the others are removed or changed. Replay starts from the last checkpoint before the first difference and only redraws the dirty tiles: those the removed and changed marks touched, plus the tiles a changed mark touches on its way. A tile a changed mark reaches that a later unchanged mark also touches is first restored from the checkpoint and caught up; a tile no later mark touches is already right. Unchanged marks are redrawn only where their footprint meets the dirty tiles, and only inside them (dabs outside are placed but not painted). The result is bit for bit a full replay; later checkpoints are remapped to the new positions and refreshed where tiles changed. If unchanged marks changed order, the cel replays in full.

The editor keeps this record per paint cel. The CLI keeps the final tiles in `.cache/tiles/<cel>.raster` and the keys and footprints in `<cel>.marks`, so the first render after an edit updates the cached tiles the same way (without checkpoints). "Bake" turns a cel into plain pixels stored as compressed tiles and drops its strokes (later).

## Brush engine

- **Dabs.** A stroke's samples are interpolated along arc length and a dab is placed every `spacing x size` (the size at that point, taper included).
- **Tip.** Procedural round (hardness), `chalk`, or a picture (`{"image": {"image": "<name>"}}`): six library pictures drawn in code (`bristle-flat`, `bristle-round`, `sponge`, `leaf`, `grass`, `splatter`) or a PNG the bundle carries in `brushes/images/<name>.png` (dark is paint, or its alpha when it has one), with roundness, rotation (fixed, follow direction, or tilt) and seeded jitter.
- **Dual tip (M5).** A second tip stamped `count` times per dab at seeded offsets within `scatter` main radii, at `size` of the main tip and a seeded turn; the dab keeps the main tip's coverage only where the second one has paint (the most of its stamps).
- **Texture (M5).** The grain is paper noise or a picture, at a `scale`, with a `contrast`, and `pressure` fills it in on a hard press; it stays fixed on the canvas.
- **Colour dynamics (M5).** Per dab and per stroke hue, saturation and value jitter (seeded: the per-stroke offsets from the stroke's seed on a stream of their own, the per-dab ones drawn after the dab's other jitter, so brushes without colour dynamics replay exactly as before); colour from pressure (from the stroke's second colour at a light press to its colour at a full one) or along the stroke (to the second colour over `along` px). Strokes carry an optional second colour (stroke format 6, a flag bit, so strokes without it encode as before).
- **Dynamics.** Size, flow and opacity each multiply curves of pressure, tilt (0 upright to 1 flat) and speed (0 to 1 at 5 px/ms). A curve is `min + (max - min) x input^gamma`.
- **Taper.** Per stroke, by length and independent of pressure: the size eases (smoothstep) from 0 at the ends to full over the first `in` and last `out` px. Live painting can only taper the start; at pen up a tapered stroke is drawn once more with its length known, which is also what every replay does.
- **Grain.** A canvas-space texture modulates dab alpha (paper tooth).
- **Stroke buffer.** Dabs build up in an f32 coverage buffer towards a cap, the brush opacity times its opacity curve (flow vs opacity, as in Photoshop: one stroke never darkens itself past the cap, overlapping strokes do). A round tip's coverage is its profile averaged over the pixel, so a hard tip has a one pixel antialiased edge. Where the tip's falloff is under about a pixel wide (hard tips), a pixel builds up only to the coverage the dab gives it, not past it: dabs are placed a few per pixel, and building up towards the cap turned the half covered pixels along a line's edge solid, so hard lines lost their antialiasing and lines under 2 px were drawn heavier than their size. Tips with a falloff of 2 px or more build up as before, with a blend between. The stroke then composites into the layer at the stroke's opacity with the brush's blend (normal, erase).
- **Wet paint, smudge and blend (M5).** A brush's `paint` is `wet` (wetness, pickup, dilution), `smudge` (strength) or `blend` (strength). They read only the drawing they paint into (its pixels before the stroke, and the stroke's own work so far), never other layers. The stroke buffer gains a colour layer: per-dab colour (colour dynamics and wet pickup, weighted by the coverage each dab adds) or, for smudge and blend, the replaced pixels (smudge takes each pixel from where the dab was before, blend averages a ring around it at 0.3 of the radius); landing a stroke lays its per-pixel colour over the layer or moves the layer's pixels towards the replaced ones. Replay is in stroke order, so a reading stroke sees what was under it; a tile-local update rebuilds the drawing when a reading stroke comes after the first changed mark (a test checks an edit under a smudge against a full replay). Live painting reads the active drawing too, so what is drawn is what replays.
- **Paint with body (M5, S5.23).** A brush's `body` (0 to 1, 0 by default; `oil` 0.45, `oil-load` 0.8) makes its strokes lay paint height. A drawing's raster (`klad_brush::Raster`) is its colour tiles plus an optional height channel (one f16 per pixel, in the same tiles), made the first time a stroke with body lands, so drawings without body cost nothing and keep their hash. While a stroke with body is drawn, each dab keeps the highest thickness it reaches per pixel. The thickness is measured across the stroke, not from the dab's centre (the maximum over overlapping dabs would otherwise make every pixel a lip): a flat middle rising to lips where the paint is pushed to the sides, falling to nothing over an edge band of 2.5 px or a third of the half-width, whichever is wider (0.6 at most), with the same falloff at the ends of the stroke. Grooves come from a profile fixed per stroke from its seed, about one bristle per 3.5 px, placed by the distance in px from the stroke's line so the dabs' size jitter does not fill them in; they cut 30% into a loaded stroke and up to 60% as the brush runs dry (the paint thins to 55% after eight sizes of travel). The thickness grows with the square root of the brush size (a 24 px brush is 1, from 0.4 to 1.6), so a small brush lays a thin film and a big one tall ridges, and with the pressure (30% at none). When the stroke lands, the height becomes `h (1 - 0.85 a) + body a' t`, with `a` the stroke's coverage times opacity, `a'` half to all of the opacity where the coverage passes 0.35 (falling off below it, so the height has the shape of the paint, not of a soft dab's dome) and `t` that thickness: new paint pushes most of the wet paint under it aside instead of stacking on it, so the newest strokes do not stand up as separate ridges. Lock alpha lays height only where there is paint; the eraser scales it down by its coverage; smudge and blend carry height with the pixels they move, and wet paint takes it into its reservoir like colour. Height is kept in replay checkpoints and in the drawing cache (a height section after the colour tiles; engine version 5). The `relief` effect samples the height of the layer's drawings (a group: of all its paint layers) into the effect window at the view scale, eases the tallest stacks (`1.6 tanh(h / 1.6)`), blurs it by `softness`, and for each pixel moves the colour towards `highlight` where the slope faces `light`, less in dark paint (by the square root of its luminance, as a lamp shows the ridges of the lit side more than those in shadow), and multiplies it towards `shade` where the slope faces away; flat paint stays as it is. Costs on a 2048 canvas with 600 big oil-load strokes: replay 980 ms instead of 760 ms without body (the edge band, lips and caps are tables made per dab and read with interpolation), 8 MB of height, a whole compose 136 ms instead of 15 ms, one dirty tile 2.2 ms.
- **Reshaping (M5).** A stroke's `path` can be set (`set`, `klad reshape`, A in the editor): every sample keeps its pressure, tilt and timing and moves to the same fraction of the new path's length as it had of the old one. The editor and `klad strokes --json` fit a few points to a stroke (`pathedit::fit_polyline`, the simplification `klad path` uses, at 0.12 of the stroke's size between 1 and 6 px); A edits those points and writes the bent path as one `set`.

### Brushes as data

A brush is JSON. The library is built in (`crates/core/brushes/library/`: `ink` inking pen, `pencil`, `marker`, `airbrush`, `soft`, `chalk`, `eraser`, and since M5 the painting set: `flat-bristle`, `round-bristle`, `sponge`, `fog`, `leaves`, `grass`, `splatter`, `wet`, `smudge`, `blender`, `dry-brush`, `two-tone`). The brush window (F5, `editor/brushwin.rs`) edits every setting with a live sample, draws with the edits at once (as a variant id, like the quick tuning), and saves a named brush into the bundle; pictures for tips and textures come in by path or by dropping a PNG on it. The brush fingerprint covers the bundle's pictures when it has any. A tip may hold several pictures (`"more"` beside `"image"`); each dab takes one, chosen by a hash of the stroke's seed and the dab's number so other brushes' random sequences are untouched (`leaves` draws from four leaf shapes since S5.27). A bundle embeds every brush its strokes use in `brushes/<id>.json` the first time a stroke with it is written, and from then on that file defines the id for that document, so changing the library never changes an existing render. Lookups go bundle first, then library.

```json
{
  "format": "draw-anything-brush/1",
  "name": "Every key, with example values",
  "tip": { "round": { "hardness": 0.92 } },
  "spacing": 0.04,
  "roundness": 1,
  "angle": { "fixed": 0 },
  "flow": 1,
  "opacity": 1,
  "dynamics": {
    "size": { "pressure": { "min": 0.06, "gamma": 1.5 } },
    "flow": { "tilt": { "min": 1, "max": 0.6 } },
    "opacity": { "speed": { "min": 1, "max": 0.8 } }
  },
  "jitter": { "size": 0, "angle": 0, "scatter": 0 },
  "grain": { "paper": { "seed": 11, "feature": 2 }, "strength": 0.55 },
  "blend": "normal",
  "taper": [10, 24],
  "stabilizer": 24,
  "smoothing": 12
}
```

- `tip` is `{"round": {"hardness"}}` or `{"chalk": {"seed"}}`; `angle` is `{"fixed": radians}`, `"follow"` or `"tilt"`; jitter angles are radians. Everything but `name`, `tip` and `spacing` has a default and is left out when it is the default.
- `taper`, `stabilizer` (ms) and `smoothing` (ms) are defaults for new strokes and for recording; the stroke stores its own taper, so they never change a replay.
- The editor's brush panel changes size, opacity and flow per stroke. Changing hardness or the size curve makes a variant: the same id when the bundle has no such brush yet, otherwise `<id>-<6 hex of its content>`, embedded with the first stroke.

## Pixels and compositing

- Tiles are 256x256, RGBA f16, premultiplied, sRGB encoded. Blending happens in sRGB space by default (what artists expect from Photoshop); a linear document setting comes later. A raster holds its tiles behind shared pointers and copies a tile only when it is written while shared (copy on write), so cloning a raster is cheap: background threads compose frames from the editor's drawings without copying them.
- Layers are composited by Skia on F16 raster surfaces. A mask is applied by drawing the mask's cel with destination-out over the layer's content in an isolated layer. A clip group is an isolated layer holding the base's content; each clipped layer is drawn in its own isolated layer, cut to the base with destination-in (the base drawn again), and blended onto the group.
- A layer with effects, or a clip group with an adjustment in it, is drawn into its own buffer covering the visible area plus the effects' reach (the tile path draws every raster tile that buffer touches), read back as f32, run through the effects and drawn back. Adjustments read and rewrite the pixels of the surface they are composed on, which is only allowed where nothing is isolated above it (a context flag says so); a group holding one gets a buffer of its own.
- The editor caches the composite of everything below and above the active layer, so a dab only recomposites three images in the dirty region. When a layer above blends through (a blend other than normal, an adjustment, a glow that is not normal), the layers above are composed live over the cached below and the active layer instead of cached. While painting, dirty tiles widen by the reach of the effects on the active layer and the groups around it (other edits widen by the largest reach in the document), and every live preview tile in reach is handed to the compositor, so a glow on the layer being painted grows across tile edges as you paint.
- **Planes on disk (M5).** The two cached composites are kept per frame and active layer in `.cache/planes` (1 GB budget, oldest out first), keyed by the frame's layer structure, the active layer, the onion plan and the pixel-cache key of every drawing in it, with the layers' thumbnails. A lean (heavy) scene that finds them loads only the active drawing's pixels (and its onion ghosts) and the other drawings' strokes and edit records from the pixel cache. Preparing frames writes them too, and the ruler's blue line counts a frame with planes and the active drawing cached as drawable.
- Frame keys read a stroke file only when its size, time or inode changed (writes are atomic renames, so a rewrite always gets a new inode); an edit no longer clears them.
- **Onion skin** (M3) is computed in `klad-render` (`onion`), one piece of code for the CLI, the editor's canvas and its frame cache. For a layer at a frame it lists the drawings before and after the current one: counted in drawings (the exposures before and after, each drawing once at its nearest distance, the current drawing and links to it skipped) or in frames (the drawings shown 1, 2, ... frames away). Opacity is `opacity x falloff^(distance - 1)` (defaults 0.5 and 0.6, 2 before and 2 after); those before are tinted red and those after green (`rgb x 0.25 + tint x alpha x 0.75`) unless the tint is off. In a looping range the count wraps around inside the range, so the last drawing of a cycle shows the first. The ghosts of a layer are composed (furthest first, f32 per pixel, on tiles in parallel, deterministic) into one raster, which the compositor draws right under that layer, outside its opacity, blend and mask; the ghosts of a clip group's layers go under the whole group. Hidden layers show none.
- **Sheets** (M3): `klad render --sheet` lays frames out in a grid (columns about square, `--columns`), each cell the frame at `--cell` px on its longest side with its frame number, a `hold` mark when it looks exactly like the frame before, and per layer (top first, listed in the heading) the cel it shows: `c5` starts a drawing, `|c5` holds it, `c9>c1` a link, `.` blank. `--drawings` merges frames that look the same into one cell titled with their range. A clip's sheet is headed with the clip's name and its fps. Frames that look the same are composed once; drawings load in batches under 768 MB, so long sheets of big canvases stay in memory.
- Export (`klad export`) renders the image, or one layer or group alone (a clipped layer alone stays clipped to its base's shape), at a frame, at a scale from 1/16 to 8, on transparency unless `--background`. Vector nodes are drawn at the export scale. Above full size the paint is drawn again at the export size: each drawing's marks are scaled (`markedit::transform_mark`: samples, sizes, tapers and cuts; fill coverage resampled bilinearly) and replayed with the brushes at that scale (`BrushSet::at_scale`: grain scaled with it, speed and bristle spacing measured in canvas px), the rasters drawn one to one (`Ctx::detail`), so lines stay crisp and textures keep their size; sprite sheets and frames do the same with their vector cels rasterized at that size. That replays without the cache (the lemons at 2x: 5.5 s instead of 0.7 s). Below full size the cached rasters are mipmapped down. PNGs are written by `klad-render/pngwrite.rs` on every core: rows filtered in parallel (the filter with the smallest sum per row), compressed in strips of 256 KB as one deflate stream (each strip ends on a sync flush, the last finishes it), in IDAT chunks of 1 MB, with an sRGB chunk; the strips depend on the row size only, so the bytes are the same on any machine (2400x1800: 115 ms instead of Skia's 457 ms, the same size within 2%). 8-bit PNGs are ordered-dithered (8x8 Bayer) from the f16 pixels, colour and alpha, so gradients do not band; values within an eighth of a level of an 8-bit value are written as that value, so flat colours stay flat. `--depth 16` writes 16-bit PNG. Working renders (`klad render`, `klad hash`) stay undithered so their hashes hold.

## The agent interface: `klad` CLI

Stateless: read the bundle, apply, write atomically, optionally render. Output is short text by default, `--json` for structure.

Every command with its options is in `docs/cli.md`, which `klad reference` (hidden) writes and a test keeps current. `klad-client` (`crates/client`) runs the commands from Rust: `Klad` finds the binary (`KLAD` or the path), `Drawing` applies op lines through `klad apply` and reads `ls`, `show`, `strokes`, `notes` and `selection` as JSON.

An error is one line on stderr (`error: reading a.draw/doc.json: No such file or directory`) and exit code 1, whatever `RUST_BACKTRACE` says; a bug (a panic) is one line too, with where it happened and where to report it. `KLAD_BACKTRACE=1` prints the whole chain and the backtrace instead.

| Command | Purpose |
|---|---|
| `klad new <bundle> [--width --height --layers --background --fps --frames --sketch]` | create (`--sketch` adds a vector layer named sketch on top); the editor's New makes bundles with the same code |

## The editor

- Canvas: pan, zoom, rotate; pen pressure, tilt and eraser end; 120 Hz on Apple Silicon. The window around the canvas is a neutral grey (`theme::SURROUND`), so colours read true.
- Layout (M4 batch 1): a tool strip on the left (the tools with their key letter, undo and redo, and at its foot settings, numbers and the command palette); a dock on the right holding panes (colour and brush, layers, inspector, notes for the agent, history), each with a title row that folds it, closes it and, dragged at its top edge, resizes the pane above; the timeline along the bottom, resizable and foldable to its toolbar; a status line under everything. Panes share the dock's height: they keep the sizes the user gave them, the last open one takes what is left, and when they do not fit they shrink towards their minimums and scroll inside (`layout::Layout::bodies`). Tab hides every panel but the status line, shift Tab the dock. Which panels are open, the dock's width, the timeline's height and each pane's size are kept in the user's settings (`layout`) and restored, clamped to the window. Pen calibration lives in the settings window (cmd ,); the performance numbers in a numbers window that can stay open over the canvas.
- Commands (M4 batch 1): every editor action is a `Cmd` in one list (`commands.rs`): an id (`tool.brush`, `drawing.new`, kept in settings), a name in plain words, a Phosphor icon, a group, its keys or the hold that triggers it, whether a held key repeats it, and a line on what it does. Keys, the strip, panel buttons, the timeline's buttons and context menu, and the palette all run commands through `Editor::invoke`, which first asks `can_run` (a reason when it cannot, shown as a refusal) and remembers the last twelve run. A key matches only with exactly its modifiers (shift K is not K); key repeats run commands that repeat (`=`, `[`, cmd Z) and frame steps only once the frame on screen caught up. cmd K opens the palette: type to filter (name start, then a key, a word, a substring, the letters in order, the group; hyphens ignored, so "inb" finds in-between), arrows and Return run, rows grey out with the reason, recent commands first; `?` opens it too. Every control has a hover hint after 0.35 s (from its command where there is one) and is at least 24 pt high; a test walks every control of every panel and window to keep it so.
- Tool options and selections (M4 batch 2): a bar over the canvas holds the active tool's settings (brush: picker, size, opacity, flow, and a "more" menu for hardness, lightest size, curve, taper, stabiliser and smoothing; fill: reference, gap, tolerance, grow, opacity; strokes: cut at the lasso edge, select all; points: corner, smooth, simplify, make it a path). The strip shows the eraser while the eraser brush or the pen's eraser end is on, and two colours (the current one over the second; X or a click swaps them; picking a colour from a swatch, the hex field or the eyedropper makes the old one the second). cmd alt drag sideways on the canvas sizes the brush (doubling every 120 pt), the circle staying where the drag began. H flips the view left-right (the view's mappings and the GPU matrix mirror; the document does not change); the status line's zoom takes a click for 100% and a double-click to fit, its rotation a click to turn upright. A selection bar sits under (or over) the selection's box: for strokes flips, quarter turns, recolour, thinner, thicker, opacity, copy, paste, duplicate in place, delete, deselect; for a shape flips (sx or sy negated and its rotation mirrored), quarter turns, duplicate in place (an `add` of the node without ids, above it), delete, deselect; for points corner, smooth, nudges, delete. Arrows nudge strokes, a shape or points by 1 px, 10 px with shift. Strokes select across layers (M5 batch 2 round 1): cmd or shift click on rows in the layers panel adds paint layers to the active one (marked with a blue edge); S then lassos, clicks and selects all on all of them, and the selection (one part per layer) moves, turns, scales, flips, recolours, cuts at the lasso edge, copies and deletes as one edit, each layer's marks staying on their layer. A selection on several layers drags as its outline (no GPU lift) and lands on release; copies of several layers paste back into their own layers, a copy of one layer into the active one. The strip's panels button lists the five panels and the timeline with a tick each, so a closed panel always has a way back. U draws rectangles and ellipses on a vector layer (shift for a square or circle, alt from the centre, rounded corners for rectangles; fill, outline and width shared with the pen, the fill in the first colour and the outline in the second, as for the pen's paths) as `rect` and `ellipse` nodes. Mirror painting (the brush bar's "mirror" and its axis) paints every stroke's mirror image as it is drawn, in a second stroke buffer landed after the first, and commits both as plain marks in one history step. Handles are drawn at 12 pt and hit within 12 pt (`grab`); shapes whose rotation is a quarter turn get edge handles too (`lift::stretched` scales their own axis). Pen events that arrive while a shape move or point edit is being written are held and replayed in order after it. The colour and brush pane shows the palette (swatches drag to reorder; the x in a hovered swatch's corner, or a right-click, removes it), recent colours, size presets and the brushes as tiles, each with a sample stroke drawn by `klad-brush` once per brush definition.
- Messages and jobs (M4 batch 1): every result, refusal and error goes through `Editor::say` with a tone (info, done, refused, error). Done and refused messages show for 3.5 and 6 s as a toast next to the pointer where the user acted (jobs' messages at the bottom right), errors until dismissed, info only in the status line; the status line shows the latest message (a click opens the message log, the last 200 with times), the frame, where the next stroke goes ("draws into c12 on lines, frames 4 to 7"), running jobs with a cancel button, slow internal work (preparing a selection, drawing an edited path, loading a frame), zoom and rotation. Times that used to be status text (stroke, fill, edit, undo, sync, frame step, last play, last job) are kept by name for the numbers window. Background jobs (in-betweens, Godot export) run the same `klad` binary through one job list (`jobs.rs`); when the CLI exits with code 75 (the document changed while it computed) the job runs again, up to three times, so an edit made in the editor meanwhile is never overwritten.
- Tools: brush, eraser, smudge, fill (inside lines, gap closing), lasso select and transform, move/rotate/scale handles, path point editing, eyedropper.
- Stroke select (S, M2): click picks the topmost stroke or fill on the active paint layer under the pointer, a dragged loop picks every stroke whose samples are all inside it and every fill whose pixels are, shift adds or toggles. With "a lasso cuts strokes at its edge" (on by default) the loop also takes the parts of strokes and fills crossing it: the selection shows the dashed lasso and the parts that will move, and the first edit (move, recolour, delete, ...) writes one `lasso` op that splits them, after which the selection is the moved marks. The selection shows as thin lines and a box with corner handles (uniform scale), edge handles (stretch one axis; dragging past the other edge flips) and a rotate knob; dragging moves it on the GPU (the selected marks drawn alone, over the cel replayed without them) and release writes one `transform` or `lasso` op. The inspector recolours (the current colour), makes thinner or thicker, sets opacity, flips left-right or up-down and deletes, each as one history step. The selection is shared with the agent as addresses.
- Layers (M2 batch 4): the inspector sets clip to the layer below and lock alpha, adds a mask (empty, or hiding all), turns it on and off, removes it, and "paint on the mask" makes the mask the active layer (it also has its own row under its layer). Painting on a mask hides the layer under the strokes; the eraser shows it again. While a mask is active, what it hides is tinted red ("show the mask in red", on by default), and the brush panel says whether the brush or the eraser is on. The brush and fill tools record lock alpha from the active layer.
- Live previews and clipping: the editor composes the active layer between cached images of everything below and above it only when that is exact (the active layer and the groups around it are not clipped, masked or a clip base); otherwise each dirty tile composes the whole stack. The GPU lift of a dragged shape or of selected strokes falls back to the outline (the result appears on release) when the dragged layer is clipped, masked or a clip base, when a group around it is, when a layer above it uses overlay, or when a lock-alpha mark lies at or after the first selected mark in its cel. Clip groups above the dragged layer stay live: they compose as one plane with the base's blend.
- Direct select (A, M2): click a path, rect or ellipse (inside groups too) to show its points; clicking the selected shape again steps down to the next shape under the pointer, and the inspector lists them all; click or shift click points, drag on empty canvas for a box; drag points or handles; alt click the outline adds a point, alt click a point toggles corner and smooth, alt drag a handle breaks it; delete removes points; the inspector has corner, smooth, delete points, simplify and "make it a path". While dragging, the edited outline is drawn live; on release the edit is one `path` op whose layer is rendered in the background, then swapped in.
- Select and move (V, M4 test): a press picks what is under the pen and drags it at once: a stroke or fill on the active paint layer first, then a vector shape (clicking a shape again steps to the one under it), then the topmost visible, unlocked paint layer with a mark there, which becomes the active layer. A stroke picked this way is the same selection as S makes (its bar, inspector, nudges, delete, copy), so V is the one tool for "move this". A press on empty canvas lassoes strokes on the active layer. Alt drag drags a copy: the copy is made (duplicate in place, one step) when the drag first moves, and the drag moves the copy (two history steps). A, the point editor, says so when a click lands on a brush stroke: strokes are samples, not paths.
- Pen (P, M4 test): draws vector paths on a vector layer: a click places a corner, a drag pulls out symmetric handles, a click on the first point closes the path, Return finishes it open, Esc drops it, and another tool finishes it. The path is one `add` node op into the layer at the current frame, in the current colour: closed paths are filled (unless "fill" is off) and outlined (unless "outline" is off), open ones always outlined, at the width in the options bar. On other layers it refuses and says why; the brush says so on a vector layer.
- Colour (M2): a hue ring with a saturation and value square, hex, alpha; the document palette as swatches (click picks, right-click removes, "add colour" adds the current one with an optional name, all as ops); the last 16 colours used, kept in the user's settings. Alt-click with the brush or fill tool picks the colour of the image under the pointer, shift alt-click that of the active layer.
- Fill tool (G, M2): click fills inside the lines of this layer, all visible layers or a chosen layer, with gap, tolerance, expand and opacity settings; drag a loop to lasso fill.
- Inspector gradients (M2): a shape's fill switches between none, solid, linear and radial; gradients edit their geometry and stops (position, colour, add, remove).
- Canvas mipmaps (M2): every uploaded tile brings its own mip chain (box filtered on the CPU, down to one pixel per tile), so zoomed-out views sample trilinearly instead of shimmering.
- Frames (M3): the canvas, painting, fills (their reference at that frame), selection, lifts, notes and the shared selection all work at the current frame. Painting paints into the drawing exposed there (on a link into its source, which the timeline says), and painting on a blank frame starts a drawing there. `,` and `.` step a frame, alt `,` and alt `.` jump to the previous and next drawing on the active layer, Home and End go to the first and last frame. The scene keeps drawings loaded across frames, so going back to a frame only recomposes it; a frame with drawings not loaded yet loads in a background frame job while the last frame stays on screen (drawings a job loaded before the document changed are not kept, and load again when needed; see the frame cache below). Drawings away from the current frame drop their replay checkpoints, and beyond 1 GB the least recently shown are evicted; a drawing changed from outside while it is not shown is evicted and reloads when its frame comes back.
- Timeline panel (M3), along the bottom: a frame ruler with the playhead, one row per layer top first (groups fold, a mask row opens under its layer with `[m+]`), each cel a block across its exposure (drawings blue or green for vector, links purple marked `->c1`), blanks empty. Click a cell to go to that frame and layer; drag on the ruler or on empty cells to scrub; drag the right end of a block to change its exposure (later cels of the layer move); drag a block by its first frame to move it. Buttons, the context menu and keys: new drawing (K), duplicate to the next frame (the copy is placed after the exposure, later cels move back), show a drawing here (a link, picked from the layer's drawings), unlink, delete, hold longer and shorter (`=` and `-`), insert a frame (I, shift for every layer) and remove one, fps and length fields, "+ paint" and "+ vector" layers. Every action is one op and one history step. A row of playback controls sits above the buttons: play, the loop range (drawn orange on the ruler), onion skin and its settings, the shift K exposure, and the dropped frames of the last play; each layer name has an onion dot at its right end.
- Onion skin (M3): O turns it on and off; "onion settings" in the timeline sets before and after, drawings or frames, opacity, falloff and tint; the dot at the right of a layer's name in the timeline shows that layer's onion too (the active layer always shows its own while onion is on). The scene composes the onion rasters (the same `klad-render` code as `--overlay onion`) when the frame, the active layer, a marked layer, the settings or a drawing they show change, and loads the drawings they need with the frame. The active layer's onion is part of the cached image of everything below it, so painting with onion on composes exactly what it composes without; marked layers' onions are drawn inside the below and above caches. The eyedropper and fills never see the onion.
- Frame cache and stepping (M3): the frame shown is the scene's frame (painting, the timeline and the agent channel all use it), and moving to a frame only sets it. What the canvas plane (the live, tiled GPU texture) shows catches up separately: at once when the frame's drawings are loaded and no cached picture of it exists, else 150 ms after the last step, or immediately when the pen touches the canvas. Meanwhile the frame cache shows the frame: one GPU texture per distinct picture (8-bit, premultiplied, with a CPU-made mip chain), at display resolution (the power-of-two level that the zoom needs, full size at 100% and closer), keyed by a hash of everything the picture depends on (the layer tree at that frame, the version of every drawing it shows: stroke file hashes and node hashes, the onion's ghosts when onion is on, the brushes and the level). Holds and links share a key, so they share a texture. A picture is composed by a background job that loads the drawings it is missing (kept in the scene afterwards, under the 1 GB drawing budget) and composes all tiles; at most two jobs run, plus one for the frame you just moved to. After a step the next 4 frames in that direction are composed ahead. The cache is capped at 640 MB, least recently shown first out; after every change the pictures no frame's key names any more are dropped, so an edit costs only the frames it changes. While the frame you stepped to is not on screen yet, held-key repeats are ignored (a fresh press still counts), so a held `.` shows every frame. While a mask is active with its red tint, frames are not cached.
- Heavy documents (M4 test): nothing that grows with the document runs on the UI thread. Catching the canvas up (loading the frame's drawings, the onion, and the caches of everything below and above the active layer) is a background job (`Scene::canvas_request`, `CanvasRequest::run`, `Scene::adopt`): one runs at a time, a result for a frame, active layer, revision or onion that is no longer wanted keeps only the drawings it loaded, and the next is asked for. The editor opens with nothing loaded and waits for the first job at most 400 ms; a pen press on a frame that is not ready waits at most 60 ms, then says the frame is still loading and draws nothing; clicking a layer or changing the onion only marks the canvas stale. After a catch-up the canvas tiles are composed and uploaded 64 per frame while the frame's picture stays on screen. Background work runs in its own thread pool with one core fewer than the machine has. Only the active drawing keeps replay checkpoints. A document whose frame loads more than 512 MB of drawings is heavy: it runs one picture job at a time, no prefetch, and loads the frame you stop on through the canvas job alone. Drawings evicted from memory are freed on a background thread.
- Caches on disk for heavy documents (M4 test, round 2): three layers of cache, all automatic and all thrown away safely (`.cache/` is never in git).
  - Pixels per drawing (`klad_brush::cache`, `.cache/tiles`): the replayed raster (zstd) and its edit record (each mark's key and the tiles it touches), keyed by the stroke file, the brushes, the canvas size and the engine version, shared by the CLI and the editor. A hit rebuilds the drawing's replay without painting anything (`CelReplay::with_marks`); a drawing whose file changed replays only its changed marks from the record. The CLI writes it after every load, as it always did; the editor writes it after a replay of 30 ms or more, so small drawings never touch the disk. 2 GB per bundle, least recently used out first.
  - Frame pictures (`.cache/frames`, one file per frame cache key, zstd of the 8-bit picture at its display level, mips rebuilt on load): written after a picture that took 30 ms or more to make, read instead of loading a frame's drawings. The canvas job writes the picture of the frame it prepares (in the background pool, from the rasters it already holds), so on a heavy document every frame you stop on is seen at once next time. Heavy documents ask for a picture of a frame, and prefetch, only when it is on disk. 1 GB per bundle.
  - Lean scenes: in a heavy document, once the canvas job has made the caches below and above the active layer, the other layers' pixels on the current frame are dropped (their strokes stay, so V still picks them). A drawing counts as loaded only with its pixels, so pictures and canvas jobs reload what they need from the disk cache. Edits on the active drawing never need the others (the caches below and above stand); an edit that would (a change on another layer, a vector or onion change, a structure change, a clip that makes the stack slow) marks the canvas stale and the canvas job redoes it. The eyedropper samples what is on screen, a fill that references other layers loads them from the disk cache first, the GPU lift falls back to the outline drag, and the canvas job hands over thumbnails before the pixels go.
  - Buffered frames and prepare (round 3, `editor/buffer.rs`): a strip along the top of the ruler shows, per frame, green when its picture is buffered (in the frame cache or on disk: it shows at once) and blue under it when its drawings are cached (every paint drawing of the frame holds its pixels in memory or a current pixel cache on disk: drawing there starts within seconds). A background survey works it out (stat of each picture file, the first 8 bytes of each drawing's cache file against the key of its stroke file, stroke files hashed again only when their size or time changed) whenever the revision, display level, onion, frame cache, held drawings or a disk write changes. "Prepare frames" (the lightning in the timeline header, or cmd K) buffers the loop range, else the clip under the playhead, else every frame, one frame at a time on a background thread (frames sharing a picture once): it loads each drawing through the pixel cache (writing it), makes the picture at the current display level and writes it, skips what is already there, keeps nothing in memory, shows its progress next to the button and in the status line, and stops after the current frame when pressed again. The skipped frames count; the summary says how many pictures and drawings were made.
  - Container numbers on `klad stress --frames 12` at 4096 px (30 layers of 300 strokes): a frame never seen is ready to draw on after 8.5 to 10 s (the replay, now also writing the caches); after reopening, a frame seen before is on screen in 12 to 45 ms and ready to draw on in about 3 s (30 drawings from the disk cache, then the caches below and above); drawings in memory 450 to 680 MB, down from 3.3 to 6 GB; UI frames while loading median 3.4 ms, p95 8 ms, slowest 62 to 88 ms.
- Clips (M3 batch 3): a strip above the frame numbers shows each clip as a bar (teal when it loops, amber when it plays once, with its name and its own fps), overlapping clips in lanes. Drag along empty strip to make a clip (named `clip1`, `clip2`, ..., looping, at the document's fps); click a bar to pick it; drag a bar's end to move that end. The row under the playback controls edits the picked clip, or the one under the playhead: name, loops, own fps, delete. Each change is one `clip` op and one history step. Clip edits change no pixels, so the frame cache keeps every picture.
- Playback (M3): Return plays and stops. It plays the range marked on the ruler when there is one (shift drag on the ruler, or the "loop range" fields), else the clip under the playhead (the picked clip first when it holds the playhead) at that clip's fps, looping or once (a clip that plays once stops on its last frame; from its last frame it starts over), else the whole timeline at the document's fps. A clock started at play time picks the frame from the elapsed time (`floor(t x fps)`), so playback never drifts; a frame whose picture is not ready yet is skipped and counted, and the timeline shows the dropped frames per loop. Playback shows pictures without onion, composes the loop ahead in the background and ends on the frame on screen. A pen touch on the canvas stops it.
- Frame by frame (M3): shift K makes a new drawing right after the current exposure, on ones, twos or threes (the "shift K exposes on" setting), and moves there: an open-ended last drawing first gets a hold that ends where the new one starts, later drawings move back when the new one needs the room, and the timeline grows at the end. Holding Q and moving the pointer sideways flips through the frames around the one where Q went down (one frame per 22 px), from the frame cache; letting go stays there. Holding W shows the previous drawing of the active layer (the whole frame where it starts; in a loop range the first drawing's previous is the range's last) and letting go comes back. While Q or W is held the pen does not paint.
- Copy and paste (M3 batch 4): with the stroke tool (S), cmd C keeps the selected marks (with a cut lasso, every mark inside or crossing it, copied with that cut, so only the parts inside show; marks shift-added outside it whole) and puts a line of text on the system clipboard, because egui reports cmd V only when the clipboard holds something. cmd V (any tool) copies them into the active paint layer's drawing at the current frame (on a link, its source; on an empty frame, a new drawing), in place, as one history step (one or two `copy` ops in one batch), then selects the copies with S.
- Timeline selection (M3 batch 4): shift click a cell to select from the playhead's cell (or the selection's first corner) to it, or shift drag over cells; the selection is a rectangle of frames over rows, drawn white. A click without shift or Esc clears it. Its context menu retimes it (on ones, twos or threes, fit into n frames, reverse, ping-pong, on the selected rows or on every layer) as one `retime` op, and makes in-betweens: the keys are the first row's drawing at the first selected frame and the last drawing starting inside the selection; count (or one per frame), spacing and pairing are menu fields. In-betweens, and "redo the in-betweens in the selection", run `klad inbetween` as a background process of the same binary, like "export to Godot", and the editor reloads when it ends. In-between cels show lighter, their id starred.
- Layers (M4 batch 3): one layer row (`editor/layers.rs`) is drawn by the layers pane and by the timeline's names column: eye, lock, the kind icon, the name (double-click renames it in that row; Return keeps, Esc leaves), clip and lock alpha marks, a mask chip (click paints on the mask, alt click turns it on or off, right-click opens its row in the timeline), in the timeline the onion dot and a fold caret on groups, in the pane a 40 by 28 thumbnail of the layer at the current frame (box filtered from its tiles, alpha boosted by a square root so thin ink still shows, cached per drawing and document revision, made by a background job: a row shows its last thumbnail until the new one is ready). Dragging a row moves the layer: the top or bottom half of a row puts it above or below, the middle half of a group puts it inside (the row lights up), and a mask, a group into itself or a drop beside a mask is refused with the reason (`drop_at`); the drop is one `mv` op. The pane's buttons: new paint, vector or group layer above the active one, duplicate (the copy becomes active), put in a new group, delete; the active layer's opacity and blend sit in the pane's title row. Each is one history step.
- Timeline layout and drags (M4 batch 3): the header is one toolbar row (fold, a frame field, transport, loop range and its fields, onion and its settings, shift K exposure, fps, length, zoom). Under it the selection toolbar (`editor/cells.rs`): new drawing, duplicate, link (the layer's drawings as thumbnails), unlink, delete, hold shorter, the hold as a field, hold longer, insert and remove a frame on this layer or every layer, copy cells, paste cells as copies or as links, retime (a menu: on ones, twos, threes, fit into n, reverse, ping-pong, every layer), in-between, redo in-betweens, new clip. What a press on the grid starts is decided where the press began (`press_at` and `drag_of`, tested): on the ruler it scrubs (shift marks the loop range), near a block's end it changes the hold, on the dot of a block's first cell it moves the block (the cursor is a hand there; since the M4 test only the dot, so a drag from the rest of that cell selects), on any other cell it selects (dragging extends over frames and rows). A hold drag or a move draws the block itself at its new length or place (the moved one faded where it was), not an outline; block labels stop before the grip lines at the block's end. A moved block is a `cel` `move` op, so drawings it lands on are pushed along; alt left and right move the drawing under the playhead by a frame. Clicking a clip's bar opens the clip window (name, loops, own fps, first and last frame as fields, delete, the Godot folder and export). Copied cells are the drawings and holds of the selected rows and frames (or the drawing under the playhead), pasted at the playhead on their own layers as `cel` `dup` or `link` ops in one batch; a drawing that was a link stays a link.
- In-between panel (M4 batch 4, `editor/between.rs`): "in-between" (the selection toolbar, the context menu, cmd K) opens a window instead of a menu: the first selected row's two keys as thumbnails with their frames (a frame not loaded yet says so), one on every frame or a count, spacing with the chart an animator draws between keys (key ticks at the ends, a tick per in-between where the spacing puts it), pairing (id, order, nearest shape; parts both keys have are named, they pair first), marks in one key only (leave, pop, fade, draw-on), and "make the in-betweens", which runs `klad inbetween` as a job (`between::args`). When the job ends its output is parsed into rows (`between::report`): each layer's pairs, parts and touching ends; an unpaired mark is a button that goes to the other key's frame, turns on the stroke tool and waits for one stroke to be picked, then makes the in-betweens again with that pair added to `--pair` (`pair_from`); a fill left out goes to its frame. "Check what a redo would remake" lists the in-betweens of the selection (or all) with their state from their marks' hash and authors (`redo_rows`): remade, drawn on by hand (keep them on top, the default; in-between them too; leave it) or edited (in-between it again, or leave it, the default); "redo them" runs one `klad inbetween --redo --only ... --keep-cels ... --force-cels ...`, one history step.
- History (M4 batch 4, `editor/history.rs`): the History pane lists the redo stack (as "undone" with who made the step, farthest first), a "the document is here" marker and the undo stack, latest first: who (you for the editor, the agent for the CLI), what, how long ago. Clicking a row undoes or redoes as many steps as it takes to stand right after it (`steps_to`), timed in the status line. The list is read again when the document's revision changes.
- Notes on the canvas (M4 batch 4, `editor/pins.rs`): every open note is a pin, those of other frames dimmed with their frame, done ones on this frame checked in green. With the note tool a click on a pin opens its popover (the text to edit and save, done, remove, close); elsewhere it opens a popover for a new note at that spot ("pin it"). A right click on any pin, of this frame or a dimmed one of another, goes to its frame and selects it (an accent ring and its popover); Delete removes the selected note. The Notes pane lists the open notes (a click goes to the frame and opens the pin) and the done ones folded, each can be opened again. The editor watches `.cache/notes.json`, so the agent's `klad notes --done` shows at once.
- Settings (M4 batch 4, `settings.rs`, `editor/prefs.rs`): the settings file carries a `version` (2; files without one, the M1 to M4 ones, load with the new fields at their defaults and are stamped 2), `keys` (command id to key labels such as `shift D`, only the changed ones), `uiScale` (0.75 to 2, egui's zoom factor, so every control grows with it) and `defaults` (brush and size for new windows, the shift K exposure, onion before, after and opacity, the grey around the canvas). The window has pen calibration, defaults, keys (search, change by pressing the key, no key, reset one or all) and layout. `commands::Bindings` holds the keys: a changed command's keys replace its first ones, a key another command already uses is refused and that command named (`taken_by`), holds (Q, W, space) keep their keys, and every key lookup (dispatch, hints, the palette, the strip's letters) goes through it.

- CLI forms in the editor (M5, S5.25, `editor/checks.rs`, `editor/export.rs`): refill this drawing and show gaps (the fill tool's options and the palette), fill like the first drawing (the timeline selection toolbar), a part name for the selected marks (the stroke inspector, the `part` op), show parts and show arcs of the selected mark or part over the clip (the palette), an export window (the document menu, cmd E: this frame, a layer, numbered frames or a sprite sheet, and Godot) and add a font file (the document menu and the text inspector, with the macOS open panel). The text tool (T, S5.26, `editor/text.rs`): a click starts a text on the active vector layer (or a new one when it is committed), typing shows on the canvas at once as a picture drawn by the same renderer while the node stays out of the document (an existing node is hidden in memory while it is edited), and Esc, a click outside or another tool commits it as one edit; a double click on text with V or T edits it in place. While typing the canvas holds egui's keyboard focus, so command keys type instead of switching tools. The font picker (the tool's options and the text inspector) lists klad's families drawn in their own face, the drawing's own files and, for a search, open families to download as a background `klad fonts --get` job. ## History

Every change, from the CLI or the editor, first stores a history entry in `.cache/history/undo/<seq>/`: `meta.json` (author, summary, revision, the stroke files it touches), `patch.json.zst` (the change to `doc.json`) and `files/` (the stroke files it is about to change, zstd). The patch is a list of changes found by comparing the document before and after: object keys that differ (`{"at": "/layers/3/cels/0/nodes/17", "old": {"x": 10}, "new": {"x": 35}}`, null meaning absent) and list splices where items were added, removed or moved (`"index"`, the removed and the inserted items). Lists are compared by common prefix and suffix; when the middle has the same items by id and type, the comparison goes into each of them, so a node edit in an 18,000-node document is one small change. `undo` checks that every changed key and item is still what the step left (otherwise it stops with "the document no longer matches it" and changes nothing), applies the old values in place, restores the stroke files, writes the document as a new revision and moves the reversed patch to the redo stack; any new change clears redo. An undone or redone step keeps the author and time of the change it records (since the M4 test; before that an undo wrote the undoer, so the agent's step became the user's once undone and redone). The last 100 steps are kept. Entries from before M2 batch 3 hold a whole `doc.json` snapshot and still undo. The editor syncs only the cels a node-level patch touches.

## Sync between CLI and editor

The agent may run in a Linux container while the editor runs on the macOS host, sharing the folder through a bind mount.

- Every change is an op appended to the op log in `.cache/`, with the author and `rev`.
- Writers write files atomically (temp file plus rename) and bump `rev`.
- Before a CLI edit writes, it checks that `doc.json` on disk still has the `rev` it loaded (`Bundle::ensure_unchanged`, reading only the head of the file); when another writer got there first it writes nothing, says "the document changed while this edit was being made", and exits with code 75. Edits computed before the transaction (in-betweens, fills like another drawing) are the ones with a real window; the editor's job list runs them again. `DRAW_TEST_WRITE_DELAY_MS` makes the CLI wait that long before its check, for the test that edits in the middle.
- The editor watches the bundle. When `rev` moves past its own, it applies the new ops from the log to its in-memory document.
- Undo and redo work on the shared log, so the human can undo an agent edit and the other way round.
- M0 verifies file events and atomic renames across the OrbStack mount in both directions.

## Exports

- PNG of the image, a layer or a group at a frame, at any scale from 1/16 to 8, transparent (see Pixels and compositing).
- **Animations** (M3 batch 3) take a spec: `all` (every clip, or the whole timeline as one animation `default` when there are no clips), a clip name, or a range `a-b`. Each frame of them is rendered as in a PNG export (scale, depth, `--layer`, `--background`); frames showing the same drawings are composed once, and pictures with identical pixels (after dithering) are kept once, so holds, links and repeats share a picture. A picture is trimmed to its pixels with alpha (an empty one keeps one transparent pixel). An animation is a list of exposures: runs of consecutive frames showing the same picture, each with its length in frames and its duration in ms at the animation's fps, rounded so that the durations add up to the animation's length (`round(end x 1000 / fps) - round(start x 1000 / fps)`).
- **Sprite sheets** (`--sheet`): pictures in order of first appearance are packed in rows (shelves) with `--padding` px around each, at the width among a few candidates that gives the most compact last page, starting another page when the next row would pass `--max`. Pages are `<name>.png`, `<name>-2.png`, ...; a re-export removes pages it no longer needs. The JSON (`<name>.json`) is Aseprite's array layout: `frames` lists the exposures of each animation in turn (`filename` `"<clip> <frame>"`, `frame` the rect in the page, `trimmed`, `spriteSourceSize` the trim, `sourceSize`, `duration` in ms, and `image` when the page is not the first), and `meta` has `app`, `version`, `image`, `format` (`RGBA8888`, or `RGBA16161616` for 16-bit), `size`, `scale`, `frameTags` (per clip: `name`, `from` and `to` indexing `frames`, `direction` forward, `repeat` `"1"` for clips that play once) and, with several pages, `images`. Readers of Aseprite JSON take single-page sheets as they are.
- **Numbered frames** (`--frames`): one full-size PNG per frame in order, holds repeated (`<clip>-0000.png`, ...), in a folder next to the bundle unless `-o`.
- **Godot** (`--godot`): into the folder (given, or `export.godot`; the first folder given is kept in the document as one history step, `--store` replaces a kept one) go the sheet pages, `<name>.tres` and `<name>.tscn`. The `.tres` is a `SpriteFrames` with an `ext_resource` per page (by a path relative to the `.tres`, and the page's uid from its `.png.import` once Godot has imported it), an `AtlasTexture` per picture (`region` its rect in the page, `margin` its trim: offset and the rest of the full size, so every frame is the canvas size and lines up), and one animation per clip (or `default`) with its name, `speed` (fps), `loop` and per-frame `duration` (the exposure's length in frames). The `.tscn` holds an `AnimatedSprite2D` using it, `centered = false` and `offset` the negated origin at the export scale, autoplaying the first animation. Uids of the `.tres` and `.tscn` are read back from the files a re-export replaces (new ones come from a hash of the file's path, in Godot's alphabet), so scenes that use them keep working. A container test imports an export in headless Godot (4.6 in the container) and checks names, frame counts, durations, loops, the offset and that the old uids still load after a re-export.
- Timings (container): the bounce sheet in about 0.25 s; a Godot export of 40 distinct frames of a 1024 canvas (4 layers, 60 strokes each) 2.3 s cold, 1.4 s warm, most of it PNG encoding of the 3080 px pages.
- Later: `Parallax2D` scenes (M6), `Skeleton2D` rigs (M6), SVG for vector layers.

## Risks M0 retires

1. Pen pressure and tilt in a native Rust window on macOS. Fallback: read them from `NSEvent` through `objc2`.
2. Live brush latency on the CPU at 120 Hz with large textured brushes, and replay speed. Fallback: a GPU brush engine, giving up exact parity with agent renders.
3. A 4k canvas with 30 layers panning and zooming smoothly.
4. CLI render time on a real document in the container.
5. File events and atomic writes across the container mount.

## Out of scope for now

3D, an iPad app, a Windows or Linux editor, image-model layers, multi-human collaboration.
